# 通达信交易接口探索记录

更新时间：2026-10-26。以下结论分为“已由日志/静态分析确认”和“待实机验证”，避免把推测当成接口事实。

## 目标

- 客户端已经登录时，可以在任意界面直接买入、卖出和撤单。
- 不打开下单窗口，不触发委托确认框。
- 尽量复用客户端已有登录会话、请求封装和通讯链路，不自行复刻 7703 协议。
- 所有参数尽早断言；先完整观测客户端原生请求，再实现发送。

## UI 录制确认的行为

日志：`logs/rec-20261026-143432.jsonl`，包含普通买入、卖出、融资买入、融券卖出和撤单操作。

### 闪电下单入口

- 主窗口 `WM_COMMAND`：
  - `0x13dd`：闪电买入
  - `0x1404`：闪电卖出
  - `0x1441`：闪电融资买入
  - `0x1462`：闪电融券卖出
- 随后发给图表视图的私有消息：
  - `0x1947`：买入
  - `0x1948`：卖出
  - `0x1945`：融资买入
  - `0x1946`：融券卖出
- `lParam` 看起来是客户端内部证券编号；这一含义尚未独立验证。

### 下单窗口

- 价格：`Edit`，id `12006`
- 数量：`Edit`，id `12007`
- 股东代码：`ComboBox`，id `12015`
- 报价方式：`ComboBox`，日志中闪电窗口为 id `3067`
- 提交：对下单对话框发送 `WM_COMMAND / IDOK(1)`

### 确认和结果

- 确认框标题包括“买入交易确认”“卖出交易确认”“交易确认”。
- 正文：`Static`，id `7013`
- 确认按钮：`Button`，id `7015`
- 结果框沿用 id `7013/7015`；成功正文含合同号，失败正文含错误码和原因。
- 同步 `BM_CLICK` 会被模态框阻塞；纯 UI 自动化应异步投递 `WM_COMMAND`。

### 撤单

- `WM_COMMAND 0x2716` 切到撤单页。
- 委托列表是 `SysListView32`，id `1567`，文字可从绘制层读取。
- 本次操作是双击列表行；随后对话框收到私有消息 `0x5554`。
- 确认框正文包含操作类别、买卖方向和合同编号。

### 回包通知

- 通讯层会给请求窗口发 `0x1788`。
- `wParam` 像递增请求序号。
- 按出现时机推测的 `lParam`：
  - `0x324`：委托提交
  - `0x326`：撤单
  - `0x325`：刷新查询
  - `0x33f`：开窗查询
- 上述功能号语义只由时序推断，尚未由请求对象观测验证。

## 为什么暂不直接复刻 7703

- 交易连接使用 7703；行情主要使用 7709/7711。
- `tc.dll` 含完整 OpenSSL 相关代码，底层 `WSASend/WSARecv` 很可能只能看到 TLS 密文。
- 自建 7703 客户端还需复制登录态、证书、券商扩展字段、心跳、重连和风控语义，依赖反而更多。
- 当前最短路径是复用客户端进程内已经登录的 session 和请求对象；客户端继续负责加密及网络通讯。

## 静态分析确认的内部请求链

### UI 入口不是交易协议入口

- `TC_DoLevinJy` 是闪电交易 UI 入口，不是适合直接提交委托的稳定接口。
- `JYConfirm`、`CANCLENOTIP`、`YMSENDNOCONFIRM` 是 UI 确认相关配置。
- 直接调用请求层不会经过下单窗口及其确认框。

### 请求对象

`AddinCredit.dll` 的信用委托路径观察到以下虚表调用：

- `+0x14`：初始化请求
- `+0x18`：设置功能号；信用委托观察到 `0xCA`
- `+0x1C`：写字符串字段
- `+0x24`：写整数字段
- `+0x2C`：写浮点字段
- `+0x64`：发送
- `+0x6C`：等待
- `+0x88 / +0x90`：访问响应

已观察到路由字段：

- 字段 id：`0x4C1`
- 值：`"SDX.ORDER,"`

### session 和请求创建

- 宿主对象虚表 `+0x26C` 返回 session。
- session 虚表 `+0x1C(0, 0)` 创建请求对象。
- 当前尚未确认在所有客户端版本、普通账户和信用账户中是否为同一具体实现。

## 已加入的请求追踪实现

修改文件：

- `scripts/bridge/shim/shim.c`
- `scripts/console.py`
- `scripts/console.html`

### shim

- 新增 `req on|off|clear|drain`。
- 新增 `req attach <hwnd> [object-offset]`。
- 通过 MFC42 `CWnd::FromHandlePermanent` 从所选顶层窗口取得永久 `CWnd` 对象。
- 扫描其中候选宿主指针；多个候选时只返回偏移，不擅自调用。
- 取得 session 并创建一个空请求，以确认请求虚表并安装只读透传钩子。
- 钩住初始化、功能号、字符串、整数、浮点和发送六个方法。
- 每次先记录参数，再原样调用原函数；不会修改请求参数。
- 请求事件写入容量 4096 的环形缓冲。

事件字段：

- 公共字段：`tick`、`tid`、`obj`、`op`
- `func/init`：`value`
- `str`：`id`、`aux`、`value`
- `int/float`：`id`、`value`
- `send`：`args`

### Console 录制器

- 开始录制时执行 `req on`、`req clear`。
- 每轮执行 `req drain`，以 `kind="req"` 写入同一个 JSONL。
- 停止或录制异常退出时执行 `req off`。
- 录制页新增“接入所选窗口”、可选对象偏移输入和“请求”过滤项。
- 多个宿主候选时，页面会列出可填写的偏移。

## 当前未验证和风险

以上代码只做了静态检查和 lint，尚未编译、注入或实机运行。

- MFC42 导出名及调用约定需要实机验证。
- `CWnd` 内宿主指针的自动扫描可能得到零个或多个候选。
- 唯一结构候选仍需用实际日志确认确实返回正确 session。
- 请求方法入口可能存在当前 `inline_hook` 不能识别的序言；这种情况会断言失败。
- 不同请求类型若使用不同方法实现，当前代码会因虚表目标不一致而断言。
- 普通账户 `AddinStock.dll` 是否与信用账户完全同构尚未确认。
- 尚未记录字段 id 到业务含义的完整映射，因此现在不能安全构造委托。
- 撤单功能号、路由、合同号字段和响应解析仍未知。

   - 融券卖出（如条件允许）

8. 先分析每个请求对象从 `init` 到 `send` 的完整字段序列，确认：

   - 代码、市场、方向、价格、数量、股东代码等字段 id 和类型
