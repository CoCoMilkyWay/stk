# 通达信（国金证券版）数据与交易控制台

Wine 里跑通达信客户端 `TdxW.exe`，从三条路取数、一条路操作，合成浏览器控制台（持仓、行情、下单、一键调仓）。

安装目录软链：`/home/chuyin/work/tdx/zd_gjzq` → `~/.wine/drive_c/zd_gjzq`

## 架构

```
TdxW.exe（Wine）
├── 本地文件   vipdoc/ T0002/           离线 K 线、代码表、除权
├── 进程堆     /proc/<pid>/mem          mem/     明文表：持仓 / 成交 / 挂单 / 信用账户 / 两融条款
└── shim.dll   TCP 控制通道             bridge/  窗口树 / 绘制层 / 输入 / 请求追踪
新浪           hq.sinajs.cn / quotes.sina.cn     desk/sina   持仓与调仓名单的实时行情 / K 线
通达信行情主站  connect.cfg [HQHOST]（7709）       desk/tdxhq  指数名单的实时行情 / K 线

mem/ + bridge/ + sina + tdxhq ──→ desk/（HUB 推送 · ORDERS 下单 · REB 调仓 · REC 录制）
                     ──→ console.py（HTTP + SSE）──→ web/（浏览器）
```

- 读：本地文件、进程内存、新浪、通达信行情主站；写：只经 shim 操作客户端界面，客户端自己负责登录会话与交易通讯。
- 一致性：内存表连读一致才采信，各表、各列缺了即 assert；不重试，等下一个起因。

## 二、内存明文表（`mem/`）

客户端查过的表，解密明文驻留在 `TdxW.exe` 堆里。只扫可写私有匿名段（Wine 堆约 580M，全量 0.23s）。

### 格式与流程

- 格式：GBK，`\r\n` 分行、`|` 分列，表头 `0|…|<n>|…` 带行数或定位串。
- 表（`tables`，7 张并排声明）：每张由四条互不相干的轴拼成，流程（`common`）只认这四条轴。

| 轴   | 声明                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------ |
| 形状 | `anchor` `back` `head`（组 1 为标签，命名组 `n` 为行数：有即取前 n 行，无即整块）`row` `empty` `slack` |
| 列   | `views` `cols {字段: (转型, 各布局列号…)}` `check(行)`                                                 |
| 读法 | `mode`：`live(tag)` 活动块 / `union(tag, uid, order)` 副本并集 / `ASK` / `WHOLE`                       |
| 索引 | `key`：`unique(*键)` / `tally(sums, uid)` 按代码合计 `{方向: Σ}` / `pairs` 名称 → 数值                 |

- 流程：`find` 段内找块成 `Hit(addr, tag, body, end)` → `pick` 选块 → 按址连读一致 → 解析校验 → 合并 → 索引成快照。
- 入口：`read(表们, pid)` 一遍扫全部堆段出各表快照；`follow(snap)` 按址复读，没换代回原快照、换代即重扫再 `pick`；`wait(snap)` 轮询 `follow` 等客户端重查；`ask(表, act)` act 前后各扫一遍，新冒出的命中即本次应答。
- 快照：`Snap(table, pid, mark, rows, by_code)`，不可变、`==` 即同一代；`mark` 为选中的块，`by_code` 为索引。
- 校验：块级无替换字符、列数全表一致且认识（`common.parse`）；行级各表 `check`；索引键不重；任一不过即 assert。
- 编码（`common`，上层同用）：沪深标志 0 深 / 1 沪 / 60 北（`MARKETS` → 代码前缀）；方向 买 +1 / 卖 −1；证券 = `code` `name` `market_flag`（`sec`）。
- 权限：`ptrace_scope ≠ 0` 时用 `scripts/.sudo_pass` 放开（`common.ensure_access`）。

### 四种读法（`mode`）

- 活动块（持仓）：每查网络缓冲留一份 `n = 行数` 的副本（永不更新）；客户端在用的活动块 `n = 0`、全进程唯一，不唯一即 assert。新旧活动块在同一堆段来回换址：`follow` 复读旧块比字节（约 0.03ms），换代后先只重扫该段（106M）；点「刷新」后约 100ms 换代。
- 副本并集（成交）：每查留几份副本、旧副本不即时释放、无活动块标记；成交只增不改，当日全部副本按成交编号取并集，同号逐字段一致。`same` 只扫上次各副本所在的段，冒出新副本才全量（约 0.5s）。
- ask（挂单 / 信用资产 / 融资负债）：每查留一份、客户端自己那份换址，表内无新旧标记，各份须逐字节一致。空表 `0||0||P|` 与无成交时的成交表同形，只认 ask 新冒出的块；挂单切页签自带一次查询，故切页与刷新同在 act 内。
- 全表（标的 / 担保品）：页上「查询全部」后客户端分页收应答，收齐另拼一整块；标的表头带总数，担保品表头不带、须对页上条数。两表跨市场同号（沪市债券与深市基金），以 (沪深标志, 代码) 为键。

## 三、消息桥（`bridge/`）

- 构成：`shim.dll` 注入 `TdxW.exe` 后开 TCP 控制通道；`shimctl.py` 负责编译、注入（`ensure`）与发命令（`Shim`）。
- 构建：产物按源码哈希命名 `shim_<H>.dll`，端口 `20000 + H % 10000`；改源码即换新 DLL、新端口，旧产物自动清理。
- 协议：请求一行 `cmd arg...`，应答 0..N 行 JSON 加末行 `ok` / `err <原因>`；`target` 为 `0x..` 或 `class=<类名>`。

| 类别   | 命令                                            |
| ------ | ----------------------------------------------- |
| 窗口树 | `tree` `enum` `find` `treegen` `treewatch`      |
| 控件   | `gettext` `settext` `rect` `detail` `highlight` |
| 动作   | `post` `send` `click` `clickat`                 |
| 输入   | `mouse` `key` `char`                            |
| 绘制层 | `gdi` `gdidump` `gdiwatch`                      |
| 请求   | `req on\|off\|clear\|drain` `req attach`        |
| 其它   | `noraise` `spy` `ping` `help`                   |

记录：

- 节点：`{depth,hwnd,id,class,title,rect,style,exstyle,vis,en}`；WinEvent 钩子维护变更版本号。
- 图层：`{hwnd,off,items:[[l,t,r,b,v,文字?]]}`，客户区坐标、后出的在上；`gdi` 与 `detail` 同形，`v` 分别为颜色与状态位。
- 快照 / 推送成对：`treegen` / `treewatch`（版本号）、`gdidump` / `gdiwatch`（图层）；长连接无变更 1s 推心跳 `null`。

机制：

- 子项：`detail` 在目标线程内一次读完 Button / ListBox / Header / ListView / TreeView / 弹出菜单的可见项。
- 输入：一律进程内 `PostMessage`，不动真实光标、不抢前台；鼠标投给捕获窗口或坐标下最深子窗口，键盘投给焦点窗口。
- 钉光标：交易功能树等控件只认 `GetCursorPos` / `GetMessagePos` 处的点击；`clickat` / `mouse` 投递前改写这两个入口，500ms 内回投递点。
- 不抬窗：各模块 IAT 里的 `NtUserSetWindowPos` / `NtUserDeferWindowPosAndBand` 换成去掉 z 序变化的包装；新弹出的菜单、对话框仍到最前。
- 绘制层：自绘控件（`CFQS_*` / `MHPToolBar` / `Afx*`）上的按钮只是画出来的字。`TdxW.exe` 有 VMProtect 壳、不走 IAT，Wine 的 win32u 层已是字形索引，故改写 gdi32 / user32 的 18 个绘制函数入口，按「后画盖先画」维护每个窗口可见的文字与色块。
- 卡顿：客户端查大表时界面线程卡住（担保品查询全部约 100s），走界面线程的命令随之超时；`Shim(cmd, …, timeout=)` 可放长等待。
- 管不到：内嵌 CEF 网页（消息中心等）。

## 四、交易链路

交易连接 7703（`tc.dll` 内含 OpenSSL，套接字上只见 TLS 密文），行情 7709 / 7711（明文，指数行情直连 7709，见 `tdxhq`）。交易不复刻协议：下单经 shim 操作闪电窗（界面层）；请求层是进程内已登录的 session 与请求对象，目前只追踪、不发送。

### 界面层（`desk/order.py`）

闪电窗：主窗 `WM_COMMAND` 打开，随后图表视图收一条私有消息（`lParam` 疑为客户端内部证券编号）。闪电窗只认图表当前证券。

| 委托     | 主窗命令 | 图表消息 | 控件 id（代码 / 价 / 量 / 单位 / 报价方式 / 最大可买·可卖 / 提交） |
| -------- | -------- | -------- | ------------------------------------------------------------------ |
| 买入     | `0x13DD` | `0x1947` | 12005 / 12006 / 12007 / 12016 / 3067 / 2022 / 1                    |
| 卖出     | `0x1404` | `0x1948` | 12005 / 12006 / 12007 / 12016 / 3067 / 2065 / 1                    |
| 融资买入 | `0x1441` | `0x1945` | 313 / 314 / 315 / 320 / 220 / 199 / 1                              |
| 融券卖出 | `0x1462` | `0x1946` | —                                                                  |

- 确认 / 回报：标题「买入交易确认」「卖出交易确认」「交易确认」/「提示」，正文 `Static` 7013、确认 `Button` 7015；回报成功含合同号，失败含错误码与原因。同步 `BM_CLICK` 会被模态框阻塞，一律异步投递。

### 请求层（`shim req`）

- 入口：`TC_DoLevinJy` 是闪电交易的界面入口；`JYConfirm` `CANCLENOTIP` `YMSENDNOCONFIRM` 为确认框配置。请求层下单不经下单窗与确认框。
- session：宿主对象 vtable `+0x26C` 返回 session；session `+0x1C(0, 0)` 创建请求对象。
- 请求对象（`AddinCredit.dll` 信用委托所见）：

| vtable          | 方法     |
| --------------- | -------- |
| `+0x14`         | 初始化   |
| `+0x18`         | 设功能号 |
| `+0x1C`         | 写字符串 |
| `+0x24`         | 写整数   |
| `+0x2C`         | 写浮点   |
| `+0x64`         | 发送     |
| `+0x6C`         | 等待     |
| `+0x88` `+0x90` | 访问响应 |

- 信用委托：功能号 `0xCA`，路由字段 `0x4C1` = `"SDX.ORDER,"`。
- 追踪：`req attach <hwnd> [offset]` 经 MFC42 `CWnd::FromHandlePermanent` 取顶层窗口的 `CWnd`，扫其中宿主指针（多个候选只回偏移、须显式给 `offset`），建一个空请求认出 vtable，钩初始化 / 功能号 / 字符串 / 整数 / 浮点 / 发送六个方法：先记参数、再原样调用。事件入 4096 条环形缓冲：公共 `{tick,tid,obj,op}`，`func` / `init` 带 `value`，`str` 带 `id,aux,value`，`int` / `float` 带 `id,value`，`send` 带 `args`。
- 录制：录制器开始即 `req on` `req clear`，每轮 `req drain` 以 `kind="req"` 并入同一 JSONL，停止即 `req off`。

## 五、后端（`desk/`）

### 推送（`feed` `hub`）

- `Feed`：源每变一次升一个版本，订阅者每见新版推一次，15s 无新版推心跳 `null`。
- `Jobs`：后台事务一次一件（下单 / 调仓），`{id, t, state: run|ok|err, msg, …}` 留最近几件，`run` 当前线程跑、`spawn` 后台跑，出错即停在当时、报原因。
- `Journal`：一件事一份 `logs/<名>-<时刻>.jsonl`（调仓 / 录制），每条 `{t 距开头秒数, kind, …}`，同时留尾巴推给页面。
- `Hub`：两个后台线程共用一份 `State = (持仓快照, 成交快照, 挂单快照, 信用账户, 行情)`；帧是它的纯函数 `board.view` 加刷新进度 `prog`，所据变了才重算。
- 推送线程（有订阅者才转）：每 100ms `follow` 持仓，每 60s 全量扫 `SCANNED`（持仓与成交），每 1.5s 取行情，状态变了即补取。
- 刷新线程一轮按 `REFRESH`（State 字段, 名称, 取数）：成交、持仓依次点页签与「刷新」、`common.wait` 等换代（两次查询间又有成交即再查一遍）→ `ask` 挂单 → `credit.account` 读信用资产与融资负债 → 回持仓页；每查完一样即并进 State 推帧，各样名称随 `prog.steps` 给前端。
- 起因：`request`（页上「刷新」，不等）/ `sync`（调仓，等刷完、失败即 assert）/ 有订阅者而还没刷过或距上轮满定时周期（默认 60s，0 = 关）/ 下单成功后 1s 与 6s / 客户端自己重查的持仓与成交对不上。
- 锁：界面自动化（刷新、下单、两融条款）共用 `ui.UI`，带占用者名字。
- 交易栏：刷新与两融条款开头 `ui.show_bar`，交易栏收起了（功能树不可见）即点主窗顶栏「交易」展开。
- 恢复：任一线程出错，推送线程下一轮先接回客户端（shim 不在线即重注入）、全量重扫（重找进程）。

### 持仓帧（`board`）

- 对齐：持仓、成交合计、行情同以代码为键，对齐成 (持仓, 成交合计)，持仓为空即今日清仓；一行由 标识 / 持仓 / 当日 / 盘口 四组列拼成，缺输入即整组空。
- 持仓列：量、成本、券商盈亏取自快照，市值 / 盈亏按 Δ价 × 量 平移；盈亏% = 现价 / 参考成本价 − 1。
- 当日列：当日盈亏 = 现市值 − 昨收 × 昨仓 − Σ 方向 × 额，昨仓 = 现量 − Σ 方向 × 量（毛，不扣费）；成交与持仓对不上即留空并标出。
- 占比列：市值 / 分母；仓位% 的分母由快照「市值 / 仓位」反推再随市值平移，占比的分母为总市值。
- 盘口列（`book`）：`book = {方向: 该方向吃的那侧}`，相对 micro price 算 1W / 5W / 15W 各额买卖滑点（即行内买卖按钮的三档）、±1% / ±2% 价位与市值加权合计；集合竞价（卖一 ≤ 买一）不出。

### 下单（`order`）

- 流程：步骤表 `ORDER` 即流程也即前端步骤条——行情定价 → 主窗敲代码切图表 → 打开闪电窗 → 核代码、填价量 → 确认框核代码 / 价 / 量 → 读回报；开窗 / 确认 / 回报同形「做一个动作、等它弹出的对话框」。
- 闪电窗按 (方向, 信用方式) 取 `FLASH`；委托价默认扫档价（对手盘累计恰好吃满该额的那档，与按钮滑点同口径），可选对手价 / 对手价偏 1% / 本方价；股数按委托价折、取整步长，以闪电窗最大可买 / 可卖封顶。行内按钮只有绿色（5 档吃满且滑点 < 10p）直接下，其余先弹窗确认。
- 接口：`submit` 后台跑（持仓页按钮），`place` 当前线程跑完回该单（调仓逐单）；`ord` 路推每单步骤状态，卡住即停在该步、窗口留给人工。

### 调仓（`credit` `rebal`）

- 名单：`lists/*.csv`，每行首列一个 6 位代码，可有 `code` 表头，行序即排名；名单里可买的经 `HUB.watch` 并进行情。
- 两融条款：开「标的证券查询」「担保品查询」各点「查询全部」，合成 `{代码: Term(ratio 融资保证金比例, financeable 融资标的且正常, rate 担保折算率, pledgeable 担保状态正常)}`，落盘 `data/credit/terms-<日期>.csv`，一天拉一次；只认当日的，跨日即作废。调仓页订阅时当日还没有即后台自动拉（每天至多一次，失败了等人点「更新两融名单」）。
- 账户：刷新一轮里读信用资产与融资负债，记下同一轮持仓股数与现价。
- 可用保证金：X = 现金 + S − 负债利息，S = Σ 折算率 × 非融资部分市值 + Σ g(融资部分市值 − 负债金额) − Σ 负债金额 × 融资保证金比例；融资部分股数 = min(负债数量, 持仓)，g(x) = 折算率 × x（浮盈）/ x（浮亏）。按读时校准：X(现在) = 读时客户端 X + S(现在) − S(读时)。
- 试算（每帧、每改配置即重算）：
  - 卖出：持仓表填面值（≥ 可卖市值即全卖），C' = 现金 + 回款，X' 按卖后持仓重算 + 回款，L = 最高融资额度 − 融资负债；C'、X'、L 各 × 行使比例为本次额度。
  - 买入：名单里可作担保品买入的等权补到共同目标市值 V（多了不卖）；融资标的先融资（按保证金比例从低到高，Σ 比例 × 融资额 ≤ X'、Σ 融资额 ≤ L），其余用现金（含费用 ≤ C'）；现金需求随 V、随并入只数都不减，故 V 二分到可行的最大（精度 1 元），并入下一只以上一个 V 为上界。
  - 单：卖单与买单同形 `{order, skip}`，持仓行一单、名单行融资 / 现金两腿；账户现 / 调仓后两栏同形（`_sheet`）。
  - 入选：先融资标的、后其余，按排名逐只试并入；未开仓的缺口须够一个最小单元（max(起买股数, 最小调仓单元 / 参考价) × 委托价）才收。
  - 取整：科创板起 200 股、北交所起 100 股，零股递增；其余整手；不足最小调仓单元（默认 1W）的单不做。
  - 成本：5 档滑点 + 佣金万 1 双向、印花税 0.05% 卖、过户费 0.001% 双向；出预期总资产、杠杆、维持担保比例。
- 执行（一次一件）：当日条款还没有即先拉 → 刷新 → 有挂单即停 → 试算 → 逐只卖出 → 刷新到卖量到齐（至多 120s）→ 去掉卖出重算 → 逐只融资买入 → 逐只现金买入 → 刷新。刷新皆 `HUB.sync`，每单 `ORDERS.place`；任一步失败即停、已下的单不撤。全程写 `logs/reb-<时刻>.jsonl`。

### 行情（`sina` `tdxhq` `kline`）

两源同形（`SRC`、`quotes(secs)`、`kline(sym, kind, n)`、`VOL_BAND`），各一条长连接、全进程各只此一路，每 1.5s 一轮（约 40 次 / 分）。行情带 `src`，K 线按它选源；两源代码不重。

| 源      | 取什么                                                  | 实时                                                                                     | K 线                                                                                                 |
| ------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `sina`  | 持仓、今日清仓、调仓名单                                | `hq.sinajs.cn` 批量：现价、昨收、5 档（量单位股），带 `Referer`；keep-alive 约 31ms / 次 | `quotes.sina.cn` `getKLineData`，scale 1 / 240，单次至多 1970 根；无成交的分钟没有；日线盘中不含当日 |
| `tdxhq` | 指数名单 `index.csv`（`sym,name`，如通达信自编 880xxx） | `0x053e`：现价、昨收、今开、最高、最低、额（指数无盘口）；交易日取 `0x0004`              | `0x052d`，周期 4 日 / 8 一分钟，一页至多 800 根、翻页凑满；一天恰 240 根；日线盘中含当日             |

- 通达信帧：请求 `0c | 标识 u32 | 01 | 长 ×2 | 命令号 | 体`，应答 16 字节头 + 体（两长不等即 zlib）；价为变长整数，量 / 额为通达信 4 字节浮点。建连先发两步握手（抓自客户端，含券商名与版本，不需账户；不握手的会话查什么都回空）。
- 量：新浪为股数；通达信一律取成交额（指数分钟量与日线量口径不一，分钟额逐日合计与日线额只差浮点舍入）。前端随 `src` 标「量 …手」或「额 …W」。
- 缓存（`KCache`）：落盘 `data/kline/<kind>/<sym>.csv`（`time,open,high,low,close,volume`），日线近 360 个交易日、分钟线近 7 个交易日，只含定稿的、变了才整写。增量取「定稿最后一根之后的根数上界 + 3」根，重叠部分逐根一致才接上；今日日线由实时行情合成、盖掉取到的同日那根。日线 / 分钟线同一套流程，差异只在 `Day` / `Min` 两个类的同名成员。
- 完整性：标号严格递增、分钟落在交易时段（两源同按 09:31…11:30、13:01…15:00 标号）、OHLC 自洽；分钟线落盘前与当日日线核开 / 高 / 低 / 收恰等、量在该源 `VOL_BAND` × 日线量（新浪 [0.95, 1]，通达信 1 ± 1e-6）。

## 六、控制台（`console.py` + `scripts/web/`）

- 启动：`python3 console.py [port]`（默认 8765），先 `ui.attach`（`ensure`、`noraise on`、`gdi on`），再起 HTTP 服务并 `xdg-open`。
- 路由：处理函数一律 `fn(body) → 应答`，生成器即 SSE、其余即 JSON；任何失败统一回 `{err}`。

| 接口                                              | 作用                                        |
| ------------------------------------------------- | ------------------------------------------- |
| `GET /api/ping`                                   | `{pid}`（离线为 null）                      |
| `GET /api/watch?s=路,路`                          | 所列各路合成一条 SSE，每条 `{s, r}`         |
| `POST /api/shim {cmd,args}`                       | 透传 shim 命令                              |
| `POST /api/clicktext {text,class?,title?}`        | 点画着该文字的按钮（须唯一）                |
| `POST /api/refresh`                               | 要一轮刷新（不等）                          |
| `POST /api/refresh/every {s}`                     | 定时刷新周期（0 = 关）                      |
| `POST /api/kline {code,kind,days}`                | 近 days 个交易日 K 线，kind = `min` / `day` |
| `POST /api/order {code,s,size,px,credit}`         | 闪电下单（后台），s = 1 买 / −1 卖          |
| `POST /api/reb/cfg {list?,unit?,pct?,px?,sells?}` | 改调仓配置                                  |
| `POST /api/reb/terms`                             | 后台拉两融条款                              |
| `POST /api/reb/run`                               | 后台执行调仓                                |
| `POST /api/rec {on}` / `/api/recmark {text}`      | 开停录制 / 打点                             |

| 路   | 源               | 内容                                 |
| ---- | ---------------- | ------------------------------------ |
| tree | shim `treewatch` | 窗口树版本号                         |
| gdi  | shim `gdiwatch`  | 变了的图层                           |
| pos  | `HUB.frames`     | 持仓帧与刷新进度 `prog`              |
| ord  | `ORDERS.feed`    | 最近各单步骤状态                     |
| reb  | `REB.frames`     | 名单 / 配置 / 账户 / 试算 / 后台事务 |
| rec  | `REC.feed`       | 录制器状态与新记录                   |

- 连接：浏览器对同一地址至多 6 条 HTTP/1.1 连接，故长连接至多两条：`tree,gdi,rec` 常驻，`pos,ord,reb` 在持仓页、指数页或行情页可见时开；标签转后台即全断、回前台重连。
- 页面：上栏 布局图 / 持仓 / 指数，下栏 行情 / 工具 / 列表 / 录制。
  - 布局图：按屏幕坐标与 z 序还原窗口，标准控件按类画、自绘窗口用绘制层；「交互」下鼠标、键盘原样投给客户端。
  - 列表：可折叠窗口树，自绘窗口下挂绘制元素；与布局图双向 hover、选中。
  - 持仓：持仓表（状态列 ● 今日成交 / ○ 挂单、悬停逐笔，行内买卖按钮、调仓卖出面值，金额一律标 W、两位小数、表尾合计）、账户对照（现 / 调仓后）、调仓配置与名单、各单状态；买卖默认锁住，点买 / 卖表头的「解锁买卖」后才下得了单；工具栏 数据 / 下单 / 调仓 三组同排、各一排控件、下接各自两行状态（读于几时与行情时刻 / 刷新进度与失败、最近两单、试算概要 / 后台事务）；布局定死：状态行定行数、空着也占地、超长截断（悬停看全文），账户对照与卖出各列试算未出即占位，提示、下单、报错都不挪动别处；今日清仓的行不参与排序、沉在最后；勾「隐私」即模糊代码、名称、状态与账户金额（盈亏与盈亏%、市值、账户对照各格、调仓概要的购买力 / 现金 / 每只目标、调仓名单的现市值 / 补 / 买入两腿）与调仓日志，连同其悬停提示；比例、只数、下单与调仓卖出各列照显，开关记在浏览器本地。
  - 指数：指数名单（`index.csv`）的现价、涨幅%，与持仓同帧；点行选股同持仓表。
  - 行情：分钟线（日内 / 2–4 日）、5 档盘口、日线（近周 / 月 / 年，默认月）同排，两图各一排档；前端按「代码 | 档」缓存，多取几日只为均线起头。默认放下所选全部，滚轮缩放（日线钉住现在、日内钉住开盘）、双击复原；日线涨跌幅相对现价、成本 / 现价线按盈亏着色并画成本 → 现价箭头，日内相对昨收。
  - 工具 / 录制：控件读写、原始 post / send、spy；录制界面事件与请求追踪。
