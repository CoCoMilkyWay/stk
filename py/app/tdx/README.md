## K 线二进制结构（社区公开格式，可直接解析）

### `.day`（日线，32 字节/条，小端）

| 偏移 | 长度 | 类型 | 字段          |
| ---- | ---- | ---- | ------------- |
| 0    | 4    | u32  | 日期 YYYYMMDD |
| 4    | 4    | u32  | 开盘价 ×100   |
| 8    | 4    | u32  | 最高价 ×100   |
| 12   | 4    | u32  | 最低价 ×100   |
| 16   | 4    | u32  | 收盘价 ×100   |
| 20   | 4    | f32  | 成交额（元）  |
| 24   | 4    | u32  | 成交量（手）  |
| 28   | 4    | u32  | 保留          |

文件大小恒为 32 的整数倍；条数 = size / 32。
示例 `sh600000.day`：2021-08-02 ～ 2026-07-10，共 1196 条。

### `.lc1`（1 分钟线，32 字节/条，小端）

| 偏移 | 长度 | 类型 | 字段                                                                                       |
| ---- | ---- | ---- | ------------------------------------------------------------------------------------------ |
| 0    | 2    | u16  | 打包日期：`year = dpack/2048 + 2004`，`month = (dpack%2048)/100`，`day = (dpack%2048)%100` |
| 2    | 2    | u16  | 打包时间：`hh = tpack/60`，`mm = tpack%60`                                                 |
| 4    | 4    | f32  | 开盘价                                                                                     |
| 8    | 4    | f32  | 最高价                                                                                     |
| 12   | 4    | f32  | 最低价                                                                                     |
| 16   | 4    | f32  | 收盘价                                                                                     |
| 20   | 4    | f32  | 成交额                                                                                     |
| 24   | 4    | u32  | 成交量                                                                                     |
| 28   | 4    | u32  | 保留                                                                                       |

## 运行时数据（不落盘）

### 持仓明文表（`scripts/mem/`）
- 来源：客户端查过一次持仓后，解密明文驻留在 `TdxW.exe` 堆里，扫 `/proc/<pid>/mem` 即得。只扫可写私有匿名段（Wine 堆，约 580M，全量 0.23s）。
- 格式：表头 `0||<n>||P00`；`\r\n` 分行、`|` 分列、行首 6 位代码、GBK。列布局分完整（≥22 列）与精简（18 列）两种，完整视图列号已对照客户端持仓表核过，见 `positions.COLS`。
- 选块：每次查询在网络缓冲多留一份 `n=行数` 的应答副本（历史快照，永不更新）；客户端在用的活动块 `n=0`、全进程唯一，新查询到来即释放旧块、另建新块。只认活动块，不唯一即 assert。
- 换代：新旧活动块在同一堆段来回换址，重读先只扫该段（106M）；按址复读旧块比字节（约 0.03ms）即知客户端是否重查过（`positions.follow`）。点「刷新」后约 100ms 换代。
- 接口：两方案同一协议（`common`）：快照为不可变值、`==` 即同一代；`read(pid)` 全量，`follow(snap)` 以最省的办法看换代（没换代回原快照），`common.wait(方案, snap)` 轮询 `follow` 等客户端重查。持仓快照 `Snap(pid, win, raw, held)`，`held` 为 `{代码: 持仓}`，今买 / 今卖取成 `traded = {方向: 股}`（方向 买 +1 / 卖 −1）。
- 校验：连读两次一致才采信；代码 6 位、列数一致、沪深标志合法、无替换字符、市值 ≈ 现价 × 余额，任一不过即 assert（`positions.parse`）。
- 权限：`ptrace_scope≠0` 时用 `scripts/.sudo_pass` 自动放开（`common.ensure_access`）。

### 当日成交明文表（`scripts/mem/fills.py`）
- 来源：客户端查过一次「当日成交」后明文驻留堆里。表头 `0|<日期 8 位><10 位>|<n>||P|`，其后 n 行、每行一笔：时间 / 代码 / 短名 / 全称 / 沪深标志 / 买卖 / 状态 / 价 / 量 / 额 / 成交编号 / 委托编号 / 股东代码 / ? / 委托类别。
- 选块：每次查询留几份副本、旧副本不即时释放、无活动块标记；成交只增不改，故当日全部完整副本按成交编号取并集即全量，同号须逐字段一致。副本地址集变了即客户端重查过，`follow` 即全量 `read`。全量一遍约 0.5s。
- 快照 `Fills(pid, addrs, rows, flow)`：`flow` 为按代码合计 `{代码: {qty: {方向: 股}, amount: {方向: 元}}}`，读时算好，与持仓的 `traded` 同形可直接比对。
- 校验：表头日期为今日、行数够 n；列数、时间、代码、沪深标志、买卖（买入 / 卖出）、状态（成交）、价 × 量 ≈ 额，任一不过即 assert。

### 消息桥（`scripts/bridge/`）
- 构成：`shim.dll` 注入 `TdxW.exe` 后开 TCP 控制通道；Linux 侧 `shimctl.py` 负责编译、注入（`ensure`）与发命令（`Shim`）。
- 构建：产物按源码哈希命名 `shim_<H>.dll`，端口 `20000 + H % 10000`；改源码即换新 DLL、新端口，旧产物自动清理。
- 协议：请求一行 `cmd arg...`，应答 0..N 行 JSON 加末行 `ok` / `err <原因>`；`target` 为 `0x..` 或 `class=<类名>`。

| 类别   | 命令                                            |
| ------ | ----------------------------------------------- |
| 窗口树 | `tree` `enum` `find` `treegen` `treewatch`      |
| 控件   | `gettext` `settext` `rect` `detail` `highlight` |
| 动作   | `post` `send` `click` `clickat`                 |
| 输入   | `mouse` `key` `char`                            |
| 绘制层 | `gdi` `gdidump` `gdiwatch`                      |
| 其它   | `noraise` `spy` `ping` `help`                   |

- 窗口树：节点 `{depth,hwnd,id,class,title,rect,style,exstyle,vis,en}`；WinEvent 钩子维护变更版本号。
- 快照 / 推送成对：`treegen` / `treewatch`（版本号）、`gdidump` / `gdiwatch`（绘制层）；长连接无变更 1s 推心跳 `{}`。
- 图层记录：`{hwnd,off,items:[[l,t,r,b,v,文字?]]}`，客户区坐标；`detail` 与绘制层同形，`v` 分别为状态位与颜色。
- 子项：`detail` 在目标线程内一次读完 Button / ListBox / Header / ListView / TreeView / 弹出菜单的可见项。
- 输入：一律进程内 `PostMessage`，不动真实光标、不抢前台；鼠标投给捕获窗口或坐标下最深子窗口，键盘投给焦点窗口。
- 不抬窗：把各模块 IAT 里的 `NtUserSetWindowPos` / `NtUserDeferWindowPosAndBand` 换成去掉 z 序变化的包装；新弹出的菜单、对话框仍会到最前。
- 绘制层：自绘控件（`CFQS_*` / `MHPToolBar` / `Afx*`）上的按钮只是画出来的字。改写 gdi32/user32 的 18 个绘制函数入口（`TdxW.exe` 有 VMProtect 壳、不走 IAT；Wine 的 win32u 层已是字形索引，故钩 API 入口），按"后画盖先画"维护每个窗口可见的文字与色块。
- 管不到：内嵌 CEF 网页（消息中心等）。

### 控制台（`scripts/console.py` + `console.html`）
- 启动：`python3 scripts/console.py [port]`（默认 8765）是唯一入口，依次 `ensure`、`noraise on`、`gdi on`，再起 HTTP 服务并 `xdg-open` 用系统浏览器打开。
- 接口：`GET /api/ping`；`GET /api/watch?s=路,路` 把所列各路推送（`tree` 窗口树版本、`gdi` 绘制层、`pos` 持仓帧、`ord` 各单状态、`rec` 录制器）合成一条 SSE，每条 `{s, r}`；`POST /api/shim {cmd,args}` 透传 shim 命令，`/api/clicktext {text,class?,title?}` 点画着该文字的按钮，`/api/refresh` 让客户端重查当日成交与持仓并等内存换代，`/api/kline {code,kind,days}` 取近 days 个交易日的 K 线（kind = `min` / `day`），`/api/order {code,s,size,px,credit}` 下单（s = 1 买 / −1 卖）。任何失败统一回 `{err}`。
- 推送源：`pos` `ord` `rec` 三路同一个 `Feed`（源每变一次升一个版本，订阅者每见新版推一次，15s 无新版推心跳 `{}`）；`tree` `gdi` 原样转发 shim 长连接。
- 行情页：点持仓 / 滑点表的行选股，左 K 线、右 5 档盘口与当日概要，两者等高；K 线可看分钟（日内 / 2 日 / 3 日 / 4 日，按图宽每 g 分钟并一根，g 整除 240）与日线，价格 3 位小数。
- 布局图：按屏幕坐标与 z 序还原窗口，标准控件按类画、自绘窗口用绘制层；勾「交互」后鼠标、滚轮、键盘原样投给客户端。
- 列表：可折叠窗口树，自绘窗口下挂其绘制元素（每段文字一项）；与布局图双向 hover、选中。
- 持仓：内存持仓 × 新浪实时价，列为代码 / 仓位 / 名称 / 滑点小盘口 / 当日盈亏(%) / 盈亏(%) / 总市值 / 融资市值 / 可卖市值 / 担保折算率；点表头排序，数字右对齐，放得下即全展开。「刷新」点客户端刷新按钮，「自动刷新」兜底（默认 60s）；下方常驻 5 档滑点表。
- 下单：持仓行「买 / 卖」各 最小单位 / 1W / 5W 按钮，`POST /api/order` 后台走闪电窗，步骤表 `ORDER` 即流程（行情定价 → 主窗敲代码切图表 → 打开闪电窗 → 核代码、填价量 → 确认框核代码/价/量 → 读回报），开窗 / 确认 / 回报同形「做一个动作、等它弹出的对话框」；闪电窗按 (方向, 信用方式) 取。`ord` 路推每单步骤状态，卡住即停在该步、窗口留给人工。委托价（对手价 / 对手价偏 1% / 本方价）与买入方式（担保品 / 融资，只管买入）为页头统一下拉。
- 工具：选中控件读写、点击、闪烁；原始 post / send；spy 抓消息。
- 同步：浏览器对同一地址至多 6 条 HTTP/1.1 连接，长连接若各占一条会把普通请求堵在排队里，故只开两条：`tree,gdi,rec` 常驻、`pos,ord` 按需，标签转后台即全断、回前台重连；标题、列表内容等无事件的变化按「轮询 fps」补拉。K 线前端按「代码 | 档」缓存，切股 / 切档先画缓存再后台重取。

### 持仓推送（`pos` 路）
- 单一后台循环 `Hub`，有订阅者才转：状态 `State = (持仓快照, 成交快照, 行情)`，帧是它的纯函数，与当前帧所据的不同才重算、推给全部订阅者。每 100ms `follow` 持仓，每 60s 全量读一次（补全进程唯一性校验）；每 1.5s 取一次行情，状态变了即补取。
- 刷新（`Hub.refresh`）：成交、持仓两方案同一写法，依次点交易栏页签与「刷新」、`common.wait` 等该方案换代，停在持仓页；两次查询间又有成交（今买 / 今卖与成交合计不符）即再连查一轮。触发：有订阅者而还没读过成交、console 下单成功后 1s / 6s、客户端自己重查了持仓却与成交对不上（交易端成交了），以及前端的手动 / 定时刷新。界面自动化（刷新、下单）共用一把锁。
- 对齐：持仓 `held`、成交合计 `flow`、行情三张表同以代码为键，对齐成 (持仓, 成交合计)，持仓为空即今日清仓；一行由 标识 / 持仓 / 当日 / 盘口 四组列拼成，每组缺了要的输入即整组空。持仓表与滑点表是同一份行的两组列。
- 列口径：量、成本、券商盈亏取自内存快照，市值 / 盈亏按 Δ价 × 量 平移（保留券商成本口径）；盈亏% = 现价 / 参考成本价 − 1；当日盈亏按成交价自算（毛，不扣费）= 现市值 − 昨收 × 昨仓 − Σ 方向 × 额，昨仓 = 现量 − Σ 方向 × 量；成交与持仓对不上时该行当日两列留空并在提示行标出；占比两列同构 = 市值 / 分母，仓位% 的分母由快照「市值 / 仓位」反推再随市值平移，滑点表占比的分母是总市值。
- 前端在持仓页或行情页可见且标签在前台时订阅，断开即停取行情。

### 行情（新浪 `hq.sinajs.cn`）
- `pytdx` 已不可用：各行情服务器（含客户端自己连的国金服务器）对其报价请求一律回 0 只。
- 新浪批量接口一次取全部持仓的现价、昨收、5 档（量单位股），需带 `Referer`；keep-alive 长连接（约 31ms/次），闲置 10s 重建，gzip。全进程只此一路请求，开几个页面都不加量，约 40 次/分，防限频。盘口不留历史。

### K 线（新浪 `quotes.sina.cn`，`POST /api/kline`）
- 接口 `CN_MarketDataService.getKLineData?symbol=&scale=&ma=no&datalen=`：scale 1 = 1 分钟、240 = 日；单次至多 1970 根；1 分钟线按 09:31 … 11:30、13:01 … 15:00 标号，无成交的分钟没有这根；日线盘中不含当日。
- 本地落盘 `data/kline/`（CSV `time,open,high,low,close,volume`，价 3 位小数、量单位股）：`day/<sym>.csv` 近 180 个交易日；`min/<sym>/<日期>.csv` 近 7 个交易日，每天收完写一个、写后不改；今日盘中分钟线只在内存，超期的随写入删掉。
- 取数只追不改：增量取「已定稿最后一根之后的根数上界 + 3」根，重叠部分须与已定稿逐根一致才接上。定稿线（日线 = 今日以前，分钟线 = 90s 以前）又越过一根才取：分钟线每分钟至多一次（午休、盘后、周末不取），日线每个交易日后至多一次；未定稿的只在内存，当日日线由实时行情合成。日线 / 分钟线是同一套流程（`KCache`），差异只在 `Day` / `Min` 两个类的同名成员（周期、标号格式、每日根数、保留天数、单次上限、定稿延迟、日内第几根、标号合法、进行中那根、盘上布局）。
- 完整性：标号严格递增、分钟落在交易时段、OHLC 自洽（取到的、读盘的都核）；分钟线每天落盘前与当日日线核对开 / 高 / 低 / 收恰等、量在 [0.95, 1] × 日线量（深市恰等，沪市分钟合计少 0.05%~0.3%）。

### 5 档盘口滑点（随 `pos` 帧推送）
新浪 5 档，相对 micro price 计算持仓在 10W/5W/1W 买、1W/5W/10W 卖下的滑点，附 ±1%/±2% 价位、实时市值占比与市值加权 aggregate。集合竞价（卖一 ≤ 买一）不出滑点。
