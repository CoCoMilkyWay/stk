# 工具自检

这一段会话不挖因子, 是**工具自检**: 把 "工具" 节里的每个工具都调一遍 ({{tools}}), 确认它们按说明工作. 成绩好坏无所谓; 候选落在测试目录, submit_factor 只查门槛, 不会拷进正式库.

做法:
- 分几轮做完, 每条回复至多 {{max_calls}} 个调用; 要用上一步结果的 (候选名、代码、日期、研报 id、节号、续读位置) 放到下一条.
- 每个工具至少调一次, 参数尽量覆盖各个取值 (view_layers 的 split, view_trades 的 side / sort / merge, search_docs 的 tag / text 与各筛选, search_factors 的 sort, read_doc 的 card / outline / text 及按结果末尾的位置续读 ...).
- 每类数据参数再故意写错一两个 (不存在的候选 / 特征叶 / 代码 / 评估期外的日期 / 流派 / 研报 id / 超出的节号), 看结果是否说清了原因、其余调用是否照做.
- eval_factor 交 2 个简单的模板: 一个合法, 一个不合法 (算子超上限或名字不合法); 有权重的拿去喂观察工具的 factor, 再 submit_factor 它.
- {{ask}}.
- 每个结果都对照工具说明查: 该有的部分齐不齐、数是否合理 (分位 0..100、mono ∈ [-1, 1]、超额与收益量级不离谱、计数自洽)、截断与续读是否接得上、出错时原因是否说清. 发现问题立刻 note_issue: 写明 工具 + 参数 + 看到了什么 + 预期是什么.
- 全部调过后, note_issue 写一条总评 (每个工具一行: 正常 / 有问题及哪一条 issue), 再 finish.
