# 挖因子 · 命令行入口

这是一套 A 股量化因子挖掘系统 (研究员开着的 GUI 程序). 你当一段挖掘会话的大脑: 经命令行 `python py/agent.py` 调系统的研究工具 —— 看数据、查研报、回测因子、把好因子提交进正式库. 会话与 GUI 内置大模型是同一套循环 / 消息 / 日志 / 存档; 研究员在 GUI 的 Agent → Mine 页实时看每个调用, 能答提问、插话、取消、回退.

本文只写怎么接上与会话怎么走; 研究上的做法 (角色 / 评估口径 / 判优 / 研究循环 / 调用协议 / 研究工具表 / 开放的特征叶与算子) 全在系统提示 (`doc`), 以它为准.

## 接入

系统开着时 (没开着命令即报错, 请研究员开), 在仓库根目录跑 `python py/agent.py <工具> [参数]`, 打印结果原文. 接口工具只有三个, 研究工具一律经 `run` 交:

| 工具   | 参数                                                                 | 做什么                                                                                |
| ------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `open` | 可选 `pool` / `level` / `hold` / `years` / `lob` / `remark` / `test` | 开新会话 (同研究员在 GUI 里按 New), 交回首条消息                                      |
| `doc`  | 无                                                                   | 本会话的系统提示                                                                      |
| `run`  | 可选 `tool` (研究工具名) + `args` (它的参数)                         | 给 `tool` = 交一个调用, 交回下一条消息; 都不给 = 接上已有外部会话 / 续等 / 取当前状态 |

参数 = JSON 对象 (缺省 `{}`) / `@文件` (读该文件的 JSON) / `-` (读标准输入; 长 JSON 用 heredoc, 免转义). 退出码 1 = 没做成, 原文写原因. `doc` 较长, 可重定向进文件按需读.

```bash
python py/agent.py open '{"remark": "用户交代的要求原话"}'
python py/agent.py doc > /tmp/doc.md
python py/agent.py run '{"tool": "list_tried", "args": {}}'
python py/agent.py run - <<'EOF'
{"tool": "view_feature", "args": {"exprs": ["bar.30m.amount_30min"]}}
EOF
python py/agent.py run
```

## 会话怎么走

1. **open**: 开新会话. 用户交代的要求原话写进 `remark` (进日志与首条消息, 研究员看得到); 作用域 `pool` / `level` / `hold` / `years` / `lob` 不给 = 研究员在 GUI 选的; `test` = 自检会话. 有会话在跑则退回, 停着的已存盘会话换下
   - 接上已有外部会话 (研究员在 GUI 载入或按继续后): 不 `open`, 直接调无参 `run`
2. **doc**: 读系统提示. 上下文被压缩过就重读
3. **循环**: 照每条消息末尾的 "下一步" 调 `run` 交一个调用 (`{"tool": "工具名", "args": {...}}`), 交回的就是下一条消息 (它的结果 + 下一步)
   - 常规只交回本条, 研究员插话附在末尾, 与做法冲突处以它为准; 首次接上有历史的会话或研究员回退后, 交回完整上下文 (以它为准, 不靠自己记的)
   - 一次只跑一个, 不并行调 `run`; 后台调用执行中至多等几分钟, 未做完先交回进度, 调无参 `run` 续等
   - 不合协议的调用不执行, 交回的下一条即重交要求 (记一步), 照改后重交
4. **挖完**: 按判优 `submit_factor` 最好的版本, 再 `finish`; 会话结束, 要再挖就 `open`

## 守的规矩

- 只经 `python py/agent.py` 取信息与行动: 本文之外不读仓库源码与 `output/` 下的数据 / 候选 / 日志 / 旧会话, 不上网, 不另跑脚本算数
- 要研究员定的事用 `ask_human` (系统提示说开放时), 不在你自己的界面停下问用户; 其余自己定
- 一直按 "下一步" 循环到 `finish` 或会话停下, 不中途收工汇报
- 遇 `ask_human` 或会话停下 (预算用完 / Cancel / 连续多条不合协议) 即交回状态: 告知研究员去 GUI 处理 (答问题 / 继续 / 回退), 他处理后调无参 `run` 接着做
