# 通达信（国金证券版）适配

Wine 里跑通达信客户端 `TdxW.exe`，实现 `live::Broker`（`live/Broker.hpp`）：读走进程堆里的明文表，写与重查经注入的 shim 驱动界面。上层（`gui/task_live`）只认 Broker，行情、持仓帧、调仓试算都在券商无关的一层（`live/Board.hpp` `live/Book.hpp` `live/Rebal.hpp`）。

安装目录软链：`/home/chuyin/work/tdx/zd_gjzq` → `~/.wine/drive_c/zd_gjzq`

## 架构

```
TdxW.exe（Wine）
├── 进程堆     /proc/<pid>/mem   Mem / Tables        明文表：持仓 / 成交 / 挂单 / 信用资产 / 融资负债 / 标的证券 / 担保品 / 资金流水
└── shim.dll   TCP 控制通道      Shim / Win          窗口树 / 绘制层 / 消息 / 输入 / 请求追踪
                                 Ui                  通达信界面：主窗 / 交易栏与功能树 / 页与查一次 / 条数标签 / 弹框
                                 Flash Credit Flow   闪电下单 / 两融条款与信用账户 / 资金流水
Tdx（Broker）  盯持仓线程 + 刷新线程 + 界面锁 Gate + 事务 txn
shim（程序）   独立调试程序：命令转发 / 探内存 / 录制 / 在线用例，直接用上面各件
```

- 读只经进程内存；写只经 shim 操作客户端界面，客户端自己负责登录会话与交易通讯。
- 客户端状态与预期不符（界面没弹出 / 内存正被改写 / 回报失败）是外部结局：`fail` 抛 `Fail`，在各轮 / 各事务的边界收成原因文本；本程序自身的不变式一律 `assert`。不重试，等下一个起因。
- 界面动作一律等客户端查完再走下一步（`ui::query` / `ui::press`，见「三、交易链路」的界面层）：查着时客户端不理切页、页一开就挪焦点，抢在前头的动作会落空。
- 等待一律经 `Until.hpp`：`poll` 等到即回、超时回空（调用方另有退路），`until` 超时即 `Fail`（报出当时的状态）。
- 交互日志经 `Trace.hpp`：shim 命令与应答、读内存的换代与应答、外部进程、Broker 的轮次 / 下单 / 两融条款按段（`Span`）一行一事件，落 `output/run/live/tdx/log/<启动时刻>.jsonl`。段内有事件才落盘，相邻同样的事件并成一行 `rep`；适配里的 `fail` 先在当时的段路径下记一行再抛；段外不记。事件种类与字段见其文件头。

## 一、内存明文表（`Mem.hpp` `Tables.hpp`）

客户端查过的表，解密明文驻留在 `TdxW.exe` 堆里。

### 堆

- `Heap`：pid + 常开的 `/proc/<pid>/mem`（各线程共用，`pread` 不带状态）；堆段 = 可读写、私有、非文件映射（Wine 堆即匿名 `rwxp`），跳过 400M 以上的段（Wine 堆约 580M）。
- `scan(形状们)`：段间并行（至多 4 线程，各一段一缓冲），同锚点的形状共一遍查找，命中按段序；`near` 给定时只扫含其中任一地址的段。`each` 逐段顺序读（`shim probe` 用）。
- `attach`：找进程（`comm` 或 `argv[0]` 为 `tdxw.exe`）、确保有读权限、开堆；`ptrace_scope ≠ 0` 时用 `output/config/live/.sudo_pass` sudo 关一次，到重启前有效。

### 表的四条轴

格式：GBK，`\r\n` 分行、`|` 分列，首行表头 `0|…|`。每张表一份声明（`Tables.hpp`），由四条互不相干的轴拼成，流程只此一份：

| 轴   | 声明                                                                                                                                          |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 形状 | `kShape{name, head, row, empty, slack}`：表头 / 数据行模式；空表算不算块；复读窗口在块尾外多留的字节                                          |
| 列   | `kViews` 各布局列数；`kCols = tuple{col<&Row::成员, as::转型>(各布局列号…)…}`（`kNone` = 该布局没有，成员 `nullptr` = 只核不存）；`check(行)` |
| 读法 | `Mode`：`Live` / `Union` / `Ask` / `Whole`                                                                                                    |
| 索引 | `Index`：`Unique<键>` 键不重 → `Keyed<行>` / `Tally` 成交按代码合计 → `Keyed<Flow>` / `Pairs` 名称不重 → 名称 → 数值原文                      |

- 模式：字面量 + 记号。`{n}` 行数、`{t}` 标签、`{d}` 不取（≥ 1 位数字；带位数 K 如 `{t8}` 即恰 K 位），`{code}` 6 位代码，`{clock}` `HH:MM:SS`，`{name}` 非数字打头的非空列，`*` 任一列，`...` 其后任意（再跟的字面量须恰为行尾）；数据行不许有 NUL。
- 表头带 `{n}` 即块只取前 n 行（后随不足 n 行 = 被覆盖了一半的旧缓冲 / 分页块，不算），不带即整块。
- 锚点：表头最长的字面段（末段连 `\r\n`）；段内找锚点，往前至多（锚点前各记号的最宽 + 字面段）字节找表头起点。
- 转型 `as::*`：`text` `name`（非空）`code` `clock` `num` `num_or`（空 = 无）`flag`（沪深标志 0 深 / 1 沪 / 60 北）`side`（买入 / 卖出 → +1 / −1）`sides`（两列买 / 卖）`groups`（三组「名称|数值|」）`is<"字面">`（只核）。

### 流程

- 一张表：扫 `Heap::scan` → 选 `Mode::choose` → 按址连读一致 `stable`（躲开 torn read）→ 解析校验 `parse` → 合并 `Mode::merge` → 索引 → 快照 `Snap{heap, mark, rows, index}`（不可变，`==` 即同一代）。
- 校验：块级 GBK 无非法字节、列数全表一致且为已知布局；行级各转型与 `check`；索引键不重。任一不过即 `Fail`。
- 读法 2 × 2：

|          | 取最新一份（没见过的） | 取累积               | 入口                                 |
| -------- | ---------------------- | -------------------- | ------------------------------------ |
| 被动换代 | `Live` 活动块          | `Union` 当日副本并集 | `follow` / `answered`                |
| act 驱动 | `Ask` act 后新冒出的块 | `Whole` 整块拼到齐   | `arm` + act + `read`（`Chain::ask`） |

- 只有 `Live` 跨次带状态（其表常驻），其余三种无状态（`Ask` / `Whole` 的表随用随建）。
- 重查一律经 `ui::query` / `ui::press` 等到客户端查完才回，其时应答已在内存里、页上条数标签写着这一问的条数 N：重查后扫一遍即是，不等、不重查。
- `follow(snap)`：没换代回原快照，换代即重扫再选（盯持仓线程用）；`answered(heap, N)`：重查后全量读，行数须恰为 N（`Union` 的 `kGrows` 可多：查完后客户端自己又查到了新成交）。
- `Chain`：接连几问（几张 act 驱动的表各 act 一次），每问查完后扫一遍，即下一问的 act 前；N = 0 即空表（空表落回同址认不出新块），N > 0 却没有新块即 `Fail`。

### 四种读法的依据

- 活动块（持仓）：每查网络缓冲留一份 `n = 行数` 的副本（永不更新）；客户端在用的活动块 `n = 0`、全进程唯一；重查即另写一块，旧块要过几秒到几十秒才释放，其间几块并存、内容不一：记下扫到过的各块（最近 256 块），新冒出的即在用的，没有新冒出的即仍是上次选的；头一次扫就几块不一（定不出）即 `Fail`，旧块释放后自愈。新旧活动块在同一堆段来回换址：`follow` 复读旧块比字节（约 0.03ms），换代后先只重扫该段；首个应答到时即换代。
- 副本并集（成交）：每查留几份副本、旧副本不即时释放、无活动块标记；成交只增不改，当日全部副本按（成交编号, 委托编号, 代码）取并集，同号逐字段一致。没换代即上次各副本所在的段里没有新副本。无成交时只回 `0||0||P|`（不带日期，认不出），并集为空、页上 0 条。
- act 后新冒出的块（挂单 / 信用资产 / 融资负债）：每查在新址留一两份、旧的不释放，同一次应答各份逐字节相同，表内无新旧标记，只认 act 后新冒出的块。空表 `0||0||P|` 与无成交的成交表同形；挂单与融资负债同形、按行首（时间 / 市场标志）可分。
- 整块拼到齐（标的 / 担保品）：页上「查询全部」后客户端分页收应答（每页一块），收齐另拼一整块（查完即有）；标的表头带总数，担保品分页块 `0||<该页行数>||P<定位串>|`（不认）、整块不带总数，行数须恰为页上条数。整块可能留着几份（每查全部一次一份），须同内容。两表跨市场同号（沪市债券与深市基金），以（市场, 代码）为键。

## 二、消息桥（`Shim.hpp` `Win.hpp`，源码 `src/live/tdx/win32/`）

- 构成：`shim.c` 注入 `TdxW.exe` 后开 TCP 控制通道；`inject.c` 远程 `LoadLibraryA`。
- 构建：交叉编译 clang + mingw 运行时优先、`i686-w64-mingw32-gcc` 次之；产物按源码哈希 H 命名 `shim_<H>.dll`、端口 `20000 + H % 10000`，落 `output/run/live/tdx/shim/`；改源码即换新 DLL、新端口，旧产物自动清理。
- 注入：DLL 拷进 wine 的 `C:\windows\temp`（不依赖 Z: 盘映射）、写端口文件，`inject.exe` 远程加载（`WINEPREFIX` 取环境变量或 `~/.wine`，目标进程名 `SHIM_TARGET_PROC` 或 `tdxw.exe`）。改了源码而客户端没重开，新版照样注入同一进程，与旧版并存（各听各的端口）：`gdi` 入口钩子叠在旧版之上照常工作，`noraise` 的 IAT 已被旧版换过、新版报 `patched 0`（旧版照拦）；两版的 `disables` 钩子会各记一次（判据只看「过了记下的数」，不受影响）。
- 接入（`win::attach`）：shim 不在线即编译 + 注入，再开 `noraise`（重扫模块，补钩注入后才加载的 DLL）与 `gdi`（首次装入口钩子并重绘全部窗口）。
- 协议：请求一行 `cmd arg...`，应答 0..N 行 JSON 加末行 `ok` / `err <原因>`；一次一条连接，shim 串行应答；`target` 为 `0x..` 或 `class=<类名>`。窗口句柄一律是 shim 给的 `0x%08x` 串（`win::Hwnd`），原样回传。

| 类别   | 命令                                            |
| ------ | ----------------------------------------------- |
| 窗口树 | `tree` `enum` `find` `treegen` `treewatch`      |
| 控件   | `gettext` `settext` `rect` `detail` `highlight` |
| 动作   | `post` `send` `regmsg` `click` `clickat`        |
| 状态   | `disables`                                      |
| 输入   | `mouse` `key` `char` `idle`                     |
| 绘制层 | `gdi` `gdidump [target]` `gdiwatch`             |
| 请求   | `req on\|off\|clear\|drain` `req attach`        |
| 其它   | `noraise` `spy` `ping` `help`                   |

记录：

- 节点：`{depth,hwnd,parent,id,class,title,rect,style,exstyle,vis,en}`，先序、depth 定父子、兄弟序即 z 序（顶层 parent 为 `0x00000000`）；WinEvent 钩子维护变更版本号。
- 查找：`find class=<类名> [id=<n>] [title=<标题>]` 在全部窗口里出相符的各节点；不相符的只取类名 / id，不读标题、不经界面线程，比整棵 `tree`（数百到近两千节点、经界面线程读可见编辑框）省得多。适配找窗口一律走它，`tree` 只给录制与小子树。
- 图层：`{hwnd,off,items:[[l,t,r,b,v,文字?]]}`，客户区坐标、后出的在上；`gdi` 与 `detail` 同形，`v` 分别为颜色与状态位。
- 快照 / 推送成对：`treegen` / `treewatch`（版本号）、`gdidump` / `gdiwatch`（图层）；长连接无变更 1s 推心跳 `null`、不收尾。

机制：

- 子项：`detail` 在目标线程内一次读完 Button / ListBox / Header / ListView / TreeView / 弹出菜单的可见项。
- 输入：一律进程内 `PostMessage`，不动真实光标、不抢前台；鼠标投给捕获窗口或坐标下最深子窗口，键盘投给焦点窗口。`idle` 回距最近一次真实键鼠输入的毫秒数（`GetLastInputInfo` 只记硬件输入，投递的不算），Broker 据此判有人在操作客户端。
- 钉光标：交易功能树等控件只认 `GetCursorPos` / `GetMessagePos` 处的点击；`clickat` / `mouse` 投递前改写这两个入口，500ms 内回投递点。
- 不抬窗：各模块 IAT 里的 `NtUserSetWindowPos` / `NtUserDeferWindowPosAndBand` 换成去掉 z 序变化的包装；新弹出的菜单、对话框仍到最前。
- 绘制层：自绘控件（`CFQS_*` / `MHPToolBar` / `Afx*`）上的按钮只是画出来的字。`TdxW.exe` 有 VMProtect 壳、不走 IAT，Wine 的 win32u 层已是字形索引，故改写 gdi32 / user32 的 18 个绘制函数入口，按「后画盖先画」维护每个窗口可见的文字与色块。`win::click_text` 在其中找文字恰为所给的项、投递其中心点的单击（候选窗口恰一个即只取它的图层）。
- 禁用计数：`disables <target>` 回窗口被禁用（`EnableWindow(FALSE)` → 同步的 `WM_ENABLE(FALSE)`）的累计次数，计在窗口属性上；首次问到某线程的窗口即给该线程常挂 `WH_CALLWNDPROC` 钩子，此后新建的窗口也记。禁用一闪即过（最短约 35ms）也记得住，轮询 `en` 位会漏。
- 卡顿：客户端查大表时界面线程卡住（担保品查询全部约 100s），走界面线程的命令（`gettext` `detail` 等）随之等待；调用方按需给长 timeout。`find` `rect` `disables` 不经界面线程，卡着时照样答。
- 管不到：内嵌 CEF 网页（消息中心等）。
- 摸客户端时序：`spy on msg=<id>`（只一种消息）/ `spy on all` 给本进程各线程挂钩、记进 512 条环形缓冲，`spy dump` 取、`spy clear` 清（`all` 很吵，边取边清）。常用：`0x111` WM_COMMAND（工具栏按钮发给宿主的命令）、`0x7` WM_SETFOCUS（焦点流转）、`0x1788` 回包（应答到了哪页、几问）。配合 `rect` 轮询 `vis` / `en`、`disables`、`gettext` 读回，即可在客户端上直接做小实验定时序。

## 三、交易链路

交易连接 7703（`tc.dll` 内含 OpenSSL，套接字上只见 TLS 密文），行情 7709 / 7711（明文）。交易不复刻协议：下单经 shim 操作闪电窗（界面层）；请求层是进程内已登录的 session 与请求对象，目前只追踪、不发送。

### 界面层（`Flash.hpp` `Ui.hpp`）

闪电窗：主窗 `WM_COMMAND` 打开，随后图表视图收一条私有消息（`lParam` 疑为客户端内部证券编号）。闪电窗只认图表当前证券。

| 委托     | 主窗命令 | 图表消息 | 控件 id（代码 / 价 / 量 / 单位 / 报价方式 / 最大可买·可卖 / 提交） |
| -------- | -------- | -------- | ------------------------------------------------------------------ |
| 买入     | `0x13DD` | `0x1947` | 12005 / 12006 / 12007 / 12016 / 3067 / 2022 / 1                    |
| 卖出     | `0x1404` | `0x1948` | 12005 / 12006 / 12007 / 12016 / 3067 / 2065 / 1                    |
| 融资买入 | `0x1441` | `0x1945` | 313 / 314 / 315 / 320 / 220 / 199 / 1                              |
| 融券卖出 | `0x1462` | `0x1946` | —                                                                  |

`flash::kKinds` 只收前三种；融券卖出的控件未录。

- 步骤（`Broker::order_steps`，一张「名 → 函数」表，各步结果写进本单上下文）：切换 → 开窗 → 填单 → 确认 → 回报；开窗 / 确认 / 回报同形「做一个动作、等它弹出的对话框」（`ui::popup`），任一步不符或超时即停在那一步、已弹出的窗口留给人工。
- 切换：通达信外部联动——注册消息 `Stock` 投给主窗，`wParam` = 市场前缀 × 10⁶ + 代码（深 6、沪 7，北交所没有），等主窗标题换成「…-名称]」；不走按键（键盘消息投给焦点窗口，焦点随客户端挪）。客户端查着时照样处理联动（实测切页后 0.05 / 0.3 / 0.5s 投的都在 0.1s 内换过来）。
- 填单：核窗内证券代码与限价委托；价按默认价的小数位格式化；股数以闪电窗最大可买 / 可卖封顶（改价后客户端未必即时重算，按价反比折一份取小）；数量单位为「元」时只收整数元、客户端按价向下折股，填 ⌈股数 × 价⌉ 并以「预估金额:…(N股)」（`8915`）核对股数。写入后客户端的 `EN_CHANGE` 处理会先改写一下，等读回恰为所写。
- 确认 / 回报：标题「买入交易确认」「卖出交易确认」「交易确认」/「提示」，正文 `Static` 7013、确认 `Button` 7015（`ui::body` / `ui::yes`）；确认框核代码 / 价 / 量；回报成功含合同号，失败含错误码与原因；等回报框、确认框、闪电窗都关了才算完。同步 `BM_CLICK` 会被模态框阻塞，一律异步投递。
- 撤单：`WM_COMMAND 0x2716` 切撤单页；委托列表 `SysListView32` id 1567（文字从绘制层读）；双击行后对话框收私有消息 `0x5554`，确认框正文含类别、方向与合同编号。
- 回包：通讯层给请求窗口（查询即该页）发 `0x1788`，`wParam` 似递增序号；`lParam` 似请求类别：下单时序里见过 `0x324` 委托 / `0x326` 撤单 / `0x325` 刷新查询 / `0x33F` 开窗查询；页的查询都回 `0x325`，持仓页一查两问，`0x325` 后约 0.5s 另回一个 `0x324`（页顶资金那行），故 `lParam` 的含义只作参考。
- 交易栏：主窗 `TdxW_MainFrame_Class`；页签与「刷新」画在 `MHPToolBar` / `MainViewBar` 上，点它们即向宿主 `AfxWnd100` id 59649 投 `WM_COMMAND`：持仓 `0x271D`、成交 `0x271B`、撤单 `0x2716`、刷新 `0x2721`（适配直接投命令，不点画出来的字）；左侧功能树 `SysTreeView32` id 59653 只给可见项，滚到顶后逐页往下找；交易栏收起（功能树不可见）即点主窗顶栏「交易」（`AfxWnd100`）展开。
- 页：宿主 59649 下的 `#32770` 子窗口，页签页与功能树开的查询页同一形——列表（表头 `SysHeader32` 的列名从 `detail` 读，认页）+ 查询键 `Button` 1140（「查 询」/「刷 新」）或 144（信用类页「刷 新」/「回到第一页」）+ 条数标签 `Static` 1243 或 166（「共N条」/「第1--N条」）。开过的页留着（隐藏），再开即显示；各页认页的列只此页有：持仓「可卖数量」、成交「成交编号」、撤单「委托价格」、信用资产「信用资金额度」、融资负债汇总「当前负债金额」、资金流水「剩余金额」、标的证券「融资保证金比例」、担保品「担保状态」（「担保折算率」持仓页也有）。三张页签页的列表都是 `SysListView32` 1567，不能按 id 认。
- 查一次（`ui::query` / `ui::press`）：切到页（切页签 / 点功能树，已在该页也算）或点页上的查询类按键（资金流水「查询」1140、「查询全部」454），客户端即重查该页。实测：
  - 查起在页显示之后 40~200ms（点页上的键则即刻）；查着时页的查询键禁用，末个应答处理完约 20ms 后恢复（持仓页两问之间一直禁用）；最短的禁用约 35ms（成交 / 撤单空表）。
  - 查着时切页签、点功能树都被吞（持仓刷新后 0.45s 内切走无效，成交 / 撤单约 0.1s）；工具栏照收点击，只是不发命令；直接投宿主命令也一样。
  - 页一显示，客户端即把焦点依次挪到页、组合框、功能树、列表（显示后约 0.1~0.2s）；起止日控件此前点了也会被抢走焦点，其后敲的键落空（或落到上回选中的段）。
  - 页一显示，条数标签先恢复成该页上回的字，查完再写这一问的，故标签不能作查完的判据。

  故：动作前等空闲（显示着的页查询键可用；没有查询键的页如下单表单算空闲），记下目标页查询键的禁用次数（act 前没有的页从 0 起），动作后等目标页显示、其禁用次数过了记下的数且此刻可用，即这一问查完：焦点已定、应答已在内存里、条数标签写着这一问的条数。

  认页、等查完只用 `find` / `rect` / `disables`（不经界面线程，查询全部卡着时照样答）；读表头的 `detail` 只在动作前（空闲）与认头一回开的新页时用，后者先 `gettext` 页把卡顿等过去。实测一轮（成交 → 持仓 → 撤单 → 信用资产 → 融资负债 → 持仓）每问 0.3~1s，标的证券 / 担保品的查询全部约 20s / 45s。
- 起止日控件（资金流水 1128 / 1131，Wine 的 `SysDateTimePick32`，源码 `dlls/comctl32/datetime.c`）：
  - 各段的位置在控件画过一次（`WM_PAINT`）后才有；没画过时点哪都命中不到段，落到末段（日）。
  - 左键按下即 `SetFocus` 并选中所点的段；失焦（`WM_KILLFOCUS`）即取消选段、丢掉未满位的数字。
  - 字符（`WM_CHAR`）不看焦点，敲进选中的段（满位即生效：年 4 位、月日 2 位）；方向键（`WM_KEYDOWN`）没焦点即不理。
  - 页一开客户端就挪焦点、并把止日重置为当日：开页那一问查完之前点、敲，键落空或落错段（实测早敲 2/4 错、查完再敲 4/4 对）。查完后点年份段、敲键不必另等，投递的消息按序处理；读回等它们处理完。

### 请求层（`shim req`）

- 入口：`TC_DoLevinJy` 是闪电交易的界面入口；`JYConfirm` `CANCLENOTIP` `YMSENDNOCONFIRM` 为确认框配置。请求层下单不经下单窗与确认框。
- session：宿主对象 vtable `+0x26C` 返回 session；session `+0x1C(0, 0)` 创建请求对象。
- 请求对象（`AddinCredit.dll` 信用委托所见）：

| vtable          | 方法     |
| --------------- | -------- |
| `+0x14`         | 初始化   |
| `+0x18`         | 设功能号 |
| `+0x1C`         | 写字符串 |
| `+0x24`         | 写整数   |
| `+0x2C`         | 写浮点   |
| `+0x64`         | 发送     |
| `+0x6C`         | 等待     |
| `+0x88` `+0x90` | 访问响应 |

- 信用委托：功能号 `0xCA`，路由字段 `0x4C1` = `"SDX.ORDER,"`。
- 追踪：`req attach <hwnd> [offset]` 经 MFC42 `CWnd::FromHandlePermanent` 取顶层窗口的 `CWnd`，扫其中宿主指针（多个候选只回偏移、须显式给 `offset`），建一个空请求认出 vtable，钩初始化 / 功能号 / 字符串 / 整数 / 浮点 / 发送六个方法：先记参数、再原样调用。事件入 4096 条环形缓冲：公共 `{tick,tid,obj,op}`，`func` / `init` 带 `value`，`str` 带 `id,aux,value`，`int` / `float` 带 `id,value`，`send` 带 `args`。
- 录制：`shim rec` 开录即 `req on` `req clear`，每轮 `req drain` 以 `kind="req"` 并入同一 JSONL，停止即 `req off`；要录交易请求先 `shim cmd req attach <闪电窗顶层 hwnd>`。

## 四、Broker（`Tdx.hpp`）

- 发布：`State` 不可变、`ver` 变即换了一份；各样为 `Got{v, at}`（值 + 客户端重查后读于几时），按一轮的刷新序 成交 / 持仓 / 挂单 / 信用账户；盯着的两样（成交、持仓）换代了才换值。
- 盯持仓线程（有人在看才转）：每 0.1s `follow` 持仓；每 60s 一遍全量扫出成交与持仓（补全「活动块唯一」校验、跟上客户端换进程）；出过错即下一步先接回客户端（shim 不在线即重注入）、全量重扫（重找进程）。
- 刷新线程一轮：成交、持仓依次切页签（切即一问）、查完 `answered` 全量读（两次查询间又有成交即对不上，连查至多 2 遍）→ 挂单、信用资产、融资负债三问接成一串 `Chain` → 回持仓页（也是一问，一样等查完再放界面锁）；每查完一样即发布，不等整轮。只刷成交的一轮（`Part::Fills`，调仓等卖单成交时轮询）只查成交、回持仓页。
- 起因：`request`（不等）/ `sync`（等刷完，失败即 `Fail`；全部的一轮也算刷过成交）/ 有人在看而还没刷过或距上轮满 `every` 秒（缺省 60s，0 = 不定时）/ 下单成功后 1s 与 6s（`kick`）/ 客户端自己重查的持仓与成交对不上。失败不自动重试，等下一个起因。
- 有人在操作客户端（`idle` < 60s）：定时与对不上这两个起因推到无输入满 60s 之后；请求、下单后、首轮照刷。
- 两融条款（`Credit.hpp`）：功能树开「标的证券查询」「担保品查询」各点「查询全部」，等查完读整表，行数须恰为页上条数（担保品近万只，客户端卡一两分钟，其间只看查询键、不经界面线程）；合成 `代码 → Term`，跨市场同号的只留 `market_of` 那只。
- 信用账户：担保资产、可融额度余量（最高融资额度 − 融资负债含费用）、负债总额、净资产、可用保证金、现金资产，各只负债（数量, 金额），与同一轮持仓（`held`，即发布的那份）。
- 资金流水（`Flow.hpp`）：功能树开「资金流水」页（等开页那一问查完才敲起止日），按 30 天一窗设起止日、点查询等查完，页上 N 条，N > 0 即取新冒出的恰 N 行的块。
- 事务：下单 / 独占 / 两融条款 / 资金流水同形 `txn(名, 字段, fn)` —— 开段、占界面锁、接上客户端、当前线程跑 fn。
- 锁：界面自动化（刷新、下单、两融条款、资金流水、调仓整批）共用界面锁 `Gate`（`Tdx.cpp`），带占用者名字，同一线程可重入。刷新一轮在各样之间 `yield`：有别路在等即先让它占、做完再接着刷（三问一串之内不让），下单至多等一样查完。

## 五、shim 独立程序（`src/live/tdx/shim/`，CMake 目标 `shim`，产物 `build/bin/shim`）

摸客户端、验收适配都在这里：靠录下的日志与断言，不靠肉眼。与 `app_main` 共用同一份适配代码（CMake 的 `app` object 库），用例测的就是生产代码本身。在仓库内运行；shim.dll 不在线即编译 + 注入。

| 子命令                  | 做什么                                                                                                    |
| ----------------------- | --------------------------------------------------------------------------------------------------------- |
| `shim cmd <命令…>`      | 原样发一条 shim 命令（命令表见 `win32/shim.c` 文件头），应答逐行 JSON                                     |
| `shim probe tables`     | 进程堆里全部明文表：址 / 副本数 / 行数 / 列数 / 表头 / 前几行；给新表找块、定列                           |
| `shim probe text <词…>` | 各词按 GBK、UTF-16LE 逐处列出址与前后字节                                                                 |
| `shim rec <秒>`         | 录制消息 / 交易请求 / 窗口树 / 绘制层的变化 → `output/run/live/tdx/rec/<时刻>.jsonl`，各条一行打到 stdout |
| `shim test [用例…]`     | 在线用例（空 = 全部不慢的；`list` 列出）；一例一行 PASS / FAIL，细节在交互日志「用例 <名>」段             |

在线用例（`Test.cpp`）钉住两类东西：适配的各条路径（各页查一次、查完即读、Chain、资金流水、两融条款），与本文实测的客户端行为（如「查着时切页签被吞」）。客户端升级后先跑一遍，哪条假设失效即知。界面动作只做查询类，不下单。
