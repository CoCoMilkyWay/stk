# 通达信（国金证券版）适配

Wine 里跑通达信客户端 `TdxW.exe`，实现 `live::Broker`（`live/Broker.hpp`）：读走进程堆里的明文表，写与重查经注入的 shim 驱动界面。上层（`gui/task_live`）只认 Broker；行情、持仓帧、调仓试算在券商无关的一层（`live/Board.hpp` `live/Book.hpp` `live/Rebal.hpp`）。客户端目录按进程映射里 `TdxW.exe` 所在定位（本机 `~/Desktop/gjzq`）。

## 架构

```
TdxW.exe（Wine）
├── 进程堆     /proc/<pid>/mem   Mem / Tables        明文表 = 请求层应答原样
└── shim.dll   TCP 控制通道      Shim / Win          窗口树 / 绘制层 / 消息 / 输入 / 禁用计数 / 虚表追踪
                                 Req Image Schema    请求层日志 / 进程映像 / 协议字典
                                 Ui                  主窗 / 交易栏与功能树 / 页与查一次 / 条数标签 / 弹框
                                 Flash Credit Flow   闪电下单 / 两融条款与信用账户 / 资金流水
Tdx（Broker）  盯持仓线程 + 刷新线程 + 界面锁 Gate + 事务 txn
shim（程序）   独立调试程序：命令转发 / 探内存 / 协议字典 / 录制 / 虚表追踪 / 在线用例，直接用上面各件
```

- 读只经进程内存；写只经 shim 操作客户端界面，登录会话与交易通讯由客户端自己负责。
- 客户端与预期不符（没弹出 / 正被改写 / 回报失败）是外部结局：`fail` 抛 `Fail`，在各轮 / 各事务边界收成原因文本；本程序自身的不变式一律 `assert`。不重试，等下一个起因。
- 界面动作一律等客户端查完再走下一步（`ui::query` / `ui::press`）：查着时客户端不理切页、页一开就挪焦点，抢在前头的动作会落空。
- 等待经 `Until.hpp`：`poll` 等到即回、超时回空，`until` 超时即 `Fail`（报出当时状态）。
- 交互日志经 `Trace.hpp`：shim 命令与应答、读内存的换代与应答、请求层的每个请求（`Req.hpp`）、外部进程、Broker 的轮次 / 下单 / 两融条款，按段（`Span`）一行一事件，落 `output/run/live/tdx/log/<启动时刻>.jsonl`；段内有事件才落盘，相邻同样的并成一行 `rep`，`fail` 先在当时的段下记一行再抛。事件种类见其文件头。

## 一、内存明文表（`Mem.hpp` `Tables.hpp`）

客户端每问的应答（解密后的明文）原样驻留在堆里：GBK，`\r\n` 分行、`|` 分列，首行表头 `0|…|`（元数据：行数、回执串，不含列名）。**列序即协议字典里该功能的出参序**（见「请求层」），行尾多一空列。

### 堆

- `Heap`：pid + 常开的 `/proc/<pid>/mem`（`pread` 无状态，各线程共用）；堆段 = 可读写、私有、非文件映射，跳过 400M 以上的段。
- `scan(形状们)`：段间并行（至多 4 线程），同锚点的形状共一遍查找，命中按段序；`near` 只扫含给定地址的段。
- `attach`：找进程（`comm` / `argv[0]` 为 `tdxw.exe`）、确保读权限（`ptrace_scope ≠ 0` 时用 `output/config/live/.sudo_pass` sudo 关一次，到重启前有效）、开堆。

### 表的四条轴

每张表一份声明，四条轴互不相干，流程只此一份：

| 轴   | 声明                                                                                                                                                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 形状 | `kShape{name, head, row, empty, slack}`：表头 / 数据行模式；空表算不算块；复读窗口在块尾外多留的字节                                                                                                                       |
| 列   | `kViews` 各布局列数、`kFuncs` 应答它的功能号；`kCols = tuple{col<&Row::成员, as::转型>("字段名", 各布局列号…)…}`（`kNone` = 该布局没有，成员 `nullptr` = 只核不存）；`check(行)`；字段名由 `shim test fields` 对协议字典核 |
| 读法 | `Mode`：`Live` / `Union` / `Ask` / `Whole`                                                                                                                                                                                 |
| 索引 | `Unique<键>` → `Keyed<行>` / `Tally` 成交按代码合计 → `Keyed<Flow>` / `Pairs` 名称 → 数值原文 / `Plain` 行原序                                                                                                             |

- 模式：字面量 + 记号。`{n}` 行数、`{t}` 标签、`{d}` 不取（带位数 K 如 `{t8}` 即恰 K 位），`{code}` 6 位代码，`{clock}` `HH:MM:SS`，`{name}` 非数字打头的非空列，`*` 任一列，`...` 其后任意；数据行不许有 NUL。表头带 `{n}` 即只取前 n 行（后随不足 n 行 = 被覆盖一半的旧缓冲 / 分页块，不算）。
- 锚点：表头最长的字面段（末段连 `\r\n`）；找到后往前至多（锚点前各记号最宽 + 字面段）字节找表头起点。
- 转型 `as::*`：`text` `name`（非空）`code` `clock` `ymd` `num` `num_or`（空 = 无）`flag`（0 深 / 1 沪 / 60 北）`side`（买入 / 卖出 → ±1）`sides`（相邻两列买 / 卖）`groups`（三组「名称|数值|」）`is<"字面">`（只核）。

### 流程

- 一张表：`Heap::scan` → `Mode::choose` → 按址连读一致 `stable`（躲 torn read）→ `parse`（块级 GBK 合法、列数全表一致且为已知布局；行级各转型与 `check`）→ `Mode::merge` → 索引（键不重）→ 不可变快照 `Snap{heap, mark, rows, index}`（`==` 即同一代）。任一不过即 `Fail`。
- 读法 2 × 2（只有 `Live` 跨次带状态、其表常驻）：

|          | 取最新一份（没见过的） | 取累积               | 入口                                 |
| -------- | ---------------------- | -------------------- | ------------------------------------ |
| 被动换代 | `Live` 活动块          | `Union` 当日副本并集 | `follow` / `answered`                |
| act 驱动 | `Ask` act 后新冒出的块 | `Whole` 整块拼到齐   | `arm` + act + `read`（`Chain::ask`） |

- 重查经 `ui::query` / `ui::press` 等到查完才回，其时应答已在内存、条数标签写着这一问的条数 N：扫一遍即是。`answered(heap, N)` 行数须恰为 N（`Union` 可多：查完后客户端又查到新成交）；`follow(snap)` 没换代回原快照。
- `Chain`：接连几问，每问查完扫一遍即下一问的 act 前；N = 0 即空表（空表落回同址认不出新块），N > 0 却没有新块即 `Fail`。

### 各表

| 表                   | 功能号      | 表头                          | 读法    | 索引                   | 行级校验                              |
| -------------------- | ----------- | ----------------------------- | ------- | ---------------------- | ------------------------------------- |
| `Positions` 持仓     | 1228 / 1114 | `0\|\|<n>\|\|P00…`            | `Live`  | `Unique<代码>`         | 市值 ≈ 现价 × 余额                    |
| `Fills` 成交         | 1108        | `0\|<日期><10位>\|<n>\|\|P\|` | `Union` | `Tally`                | 状态为成交、价 / 量为正、额 ≈ 价 × 量 |
| `Pendings` 挂单      | 1100        | `0\|\|<n>\|\|P\|`             | `Ask`   | `Unique<委托编号>`     | 状态 / 编号非空、0 ≤ 已成 < 委托量    |
| `Debts` 融资负债     | 3264        | `0\|\|<n>\|\|P\|`             | `Ask`   | `Unique<代码>`         | 数值非负                              |
| `Assets` 信用资产    | 3200        | `0\|\|<n>\|\|\|`              | `Ask`   | `Pairs`                | 首组名称非空                          |
| `Margins` 标的证券   | 3216        | `0\|\|<总数>\|\|\|`           | `Whole` | `Unique<(市场, 代码)>` | 保证金比例为正                        |
| `Collats` 担保品     | 3220        | `0\|\|0\|\|P<定位串>\|`       | `Whole` | `Unique<(市场, 代码)>` | 折算率在 [0, 1]                       |
| `CashFlows` 资金流水 | 1118        | `0\|\|<n>\|\|P\|`             | `Ask`   | `Plain`                | 带股数的行有代码                      |

- 持仓两种布局：23 列（1228）/ 18 列（1114，重登后常见，没有融资数量与担保折算率）。名称一律取「长简称」（「证券名称」对 ETF 是短码名如 `5GETF`）。各列全部字段：`shim probe schema <功能号>`。
- 读法的依据：
  - 活动块（持仓）：每查网络缓冲留一份 `n = 行数` 的副本（永不更新）；在用的活动块 `n = 0`、全进程唯一；重查即另写一块，旧块几秒到几十秒才释放，其间几块并存、内容不一：记下扫到过的块（最近 256 块），新冒出的即在用的；头一次扫就几块不一即 `Fail`（旧块释放后自愈）。新旧块在同一堆段来回换址：`follow` 复读旧块比字节（约 0.03ms），换代后先只重扫该段。
  - 副本并集（成交）：每查留几份副本、旧的不即时释放、无活动块标记；成交只增不改，按（成交编号, 委托编号, 代码）取并集、同号逐字段一致。无成交只回 `0||0||P|`（不带日期，认不出），并集为空。
  - act 后新冒出（挂单 / 信用资产 / 融资负债 / 资金流水）：每查在新址留一两份、旧的不释放，同一次应答各份逐字节相同、表内无新旧标记。空表 `0||0||P|` 与无成交的成交表同形；挂单与融资负债同形、按行首（时间 / 市场标志）可分。
  - 整块拼到齐（标的 / 担保品）：「查询全部」后客户端分页收应答（每页一块），收齐另拼一整块；担保品分页块 `0||<该页行数>||P<定位串>|`（不认），整块不带总数、行数须恰为页上条数。整块可能留几份（每查全部一次一份），须同内容。两表跨市场同号（沪市债券与深市基金），以（市场, 代码）为键。

## 二、消息桥（`Shim.hpp` `Win.hpp`，源码 `src/live/tdx/win32/`）

- 构成：`shim.c` 注入后开 TCP 控制通道；`inject.c` 远程 `LoadLibraryA`。
- 构建：交叉编译（clang + mingw 运行时优先，`i686-w64-mingw32-gcc` 次之）；产物按源码哈希 H 命名 `shim_<H>.dll`、端口 `20000 + H % 10000`，落 `output/run/live/tdx/shim/`。改源码即换新 DLL、新端口；客户端不重开时新旧版并存于同一进程、各听各的端口（`gdi` 钩子叠在旧版之上照常工作，`noraise` 新版报 `patched 0`、旧版照拦）。
- 注入：DLL 拷进 wine 的 `C:\windows\temp`、写端口文件，`inject.exe` 远程加载（`WINEPREFIX` 取环境变量或 `~/.wine`，目标进程名 `SHIM_TARGET_PROC` 或 `tdxw.exe`）。`win::attach`：不在线即编译 + 注入，再开 `noraise` 与 `gdi`。
- shim 活在客户端进程里：其 `assert` 失败即 abort 整个客户端，不弹框。客户端从桌面图标启动时 Wine 的输出进 systemd 日志（`journalctl --user | rg Assertion`）。
- 协议：一行 `cmd arg...` → 0..N 行 JSON + 末行 `ok` / `err <原因>`；一次一条连接、串行应答；`target` 为 `0x..` 或 `class=<类名>`；窗口句柄是 shim 给的 `0x%08x` 串（`win::Hwnd`），原样回传。命令表见 `shim.c` 文件头。

| 类别   | 命令                                            |
| ------ | ----------------------------------------------- |
| 窗口树 | `tree` `enum` `find` `treegen` `treewatch`      |
| 控件   | `gettext` `settext` `rect` `detail` `highlight` |
| 动作   | `post` `send` `regmsg` `click` `clickat`        |
| 状态   | `disables` `idle`                               |
| 输入   | `mouse` `key` `char`                            |
| 绘制层 | `gdi` `gdidump [target]` `gdiwatch`             |
| 虚表   | `vt hook\|ret\|unhook\|on\|off\|clear\|drain`   |
| 其它   | `noraise` `spy` `ping` `help`                   |

- 节点 `{depth,hwnd,parent,id,class,title,rect,style,exstyle,vis,en}`：先序、depth 定父子、兄弟序即 z 序。图层 `{hwnd,off,items:[[l,t,r,b,v,文字?]]}`：客户区坐标、后出的在上（`gdi` 的 `v` 为颜色，`detail` 为状态位）。`treegen`/`treewatch`、`gdidump`/`gdiwatch` 成对，长连接无变更 1s 推心跳 `null`。
- `find class=… [id=…] [title=…]` 不经界面线程、只读相符节点的标题，适配找窗口一律走它；`tree` 经界面线程读可见编辑框（数百到近两千节点），只给录制与小子树。
- 输入一律进程内 `PostMessage`：不动真实光标、不抢前台；鼠标投给捕获窗口或坐标下最深子窗口，键盘投给焦点窗口。`idle` = 距最近一次真实键鼠输入（投递的不算）的毫秒数，Broker 据此判有人在操作。
- 钉光标：功能树等只认 `GetCursorPos` / `GetMessagePos` 处的点击；`clickat` / `mouse` 投递前改写这两个入口，500ms 内回投递点。
- 不抬窗：各模块 IAT 里的 `NtUserSetWindowPos` / `NtUserDeferWindowPosAndBand` 换成去掉 z 序变化的包装。
- 绘制层：自绘控件（`CFQS_*` / `MHPToolBar` / `Afx*`）上的按钮只是画出来的字；`TdxW.exe` 有 VMProtect 壳、不走 IAT，故改写 gdi32 / user32 的 18 个绘制函数入口，按「后画盖先画」维护各窗口可见的文字与色块（`win::click_text` 据此点字）。
- 禁用计数：`disables` 回窗口被禁用（`EnableWindow(FALSE)` → 同步 `WM_ENABLE`）的累计次数；首次问到某线程即给它常挂 `WH_CALLWNDPROC`。最短约 35ms 的禁用也记得住，轮询 `en` 会漏。
- 卡顿：查大表时界面线程卡住（担保品查询全部约 45~100s），经界面线程的命令（`gettext` `detail`）随之等；`find` `rect` `disables` 照样答。
- 摸时序：`spy on msg=<id>` / `spy on all` 记进 512 条环形缓冲（`dump` 取、`clear` 清）；常看 `0x111` WM_COMMAND、`0x7` WM_SETFOCUS、`0x1788` 回包，配合 `rect` / `disables` / `gettext` 在客户端上做小实验。
- 管不到：内嵌 CEF 网页（消息中心等）。

## 三、交易链路

交易连接 7703（`tc.dll` 内含 OpenSSL，只见 TLS 密文），行情 7709 / 7711（明文）。不复刻协议：下单经 shim 操作闪电窗（界面层）；请求层（进程内 `tc.dll` 的请求对象）目前只追踪、不发送。

### 界面层（`Flash.hpp` `Ui.hpp`）

- 交易栏：主窗 `TdxW_MainFrame_Class`；页签与「刷新」画在 `MHPToolBar`（`MainViewBar`）上，点它们即向宿主 `AfxWnd100` id 59649 投 `WM_COMMAND`：持仓 `0x271D`、成交 `0x271B`、撤单 `0x2716`、刷新 `0x2721`（适配直接投命令）。功能树 `SysTreeView32` id 59653 只给可见项，滚到顶后逐页找；交易栏收起即点顶栏「交易」展开。
- 页：宿主下的 `#32770`，页签页与功能树开的查询页同形——列表（表头 `SysHeader32` 列名经 `detail` 读，认页）+ 查询键 `Button` 1140 或 144（信用类页）+ 条数标签 `Static` 1243 或 166。开过的页隐藏留着。认页的列只此页有：持仓「可卖数量」、成交「成交编号」、撤单「委托价格」、信用资产「信用资金额度」、融资负债汇总「当前负债金额」、资金流水「剩余金额」、标的证券「融资保证金比例」、担保品「担保状态」。三张页签页的列表都是 `SysListView32` 1567，不能按 id 认。
- 查一次（`ui::query` / `ui::press`）：切到页（已在该页也算）或点页上的查询类按键（资金流水「查询」1140、「查询全部」454），客户端即重查该页。实测：
  - 查起在页显示后 40~200ms（点键即刻）；查着时页的查询键禁用，末个应答处理完约 20ms 后恢复（持仓页两问之间一直禁用）。
  - 查着时切页签、点功能树都被吞（持仓刷新后约 0.45s 内，成交 / 撤单约 0.1s）；工具栏照收点击、只是不发命令，直接投宿主命令也一样。
  - 页一显示，客户端即把焦点依次挪到页、组合框、功能树、列表（约 0.1~0.2s）；此前点过的控件焦点被抢走，其后敲的键落空。
  - 页一显示，条数标签先恢复成上回的字，查完再写这一问的，故不能作查完的判据。

  判据：动作前等空闲（显示着的页查询键可用；没有查询键的页算空闲），记下目标页查询键的禁用次数，动作后等目标页显示、禁用次数过了记下的数且此刻可用，即查完（焦点已定、应答在内存、标签是这一问的条数）。认页、等查完只用 `find` / `rect` / `disables`；读表头的 `detail` 只在动作前与认头一回开的新页时用。一轮（成交 → 持仓 → 撤单 → 信用资产 → 融资负债 → 持仓）每问 0.3~1s，标的证券 / 担保品查询全部约 20s / 45s。
- 起止日控件（资金流水 1128 / 1131，Wine `SysDateTimePick32`，`dlls/comctl32/datetime.c`）：段位在控件画过一次后才有；左键按下即取焦点并选中所点的段，失焦即取消选段、丢掉未满位的数字；`WM_CHAR` 不看焦点、敲进选中的段（满位生效），方向键没焦点即不理。页一开客户端就挪焦点、并把止日重置为当日，故须等开页那一问查完才点年份段、敲键（实测早敲 2/4 错、查完再敲 4/4 对）。
- 闪电窗：主窗 `WM_COMMAND` 打开，随后图表视图收一条私有消息；只认图表当前证券。

| 委托     | 主窗命令 | 图表消息 | 控件 id（代码 / 价 / 量 / 单位 / 报价方式 / 最大可买·可卖 / 提交） |
| -------- | -------- | -------- | ------------------------------------------------------------------ |
| 买入     | `0x13DD` | `0x1947` | 12005 / 12006 / 12007 / 12016 / 3067 / 2022 / 1                    |
| 卖出     | `0x1404` | `0x1948` | 12005 / 12006 / 12007 / 12016 / 3067 / 2065 / 1                    |
| 融资买入 | `0x1441` | `0x1945` | 313 / 314 / 315 / 320 / 220 / 199 / 1                              |
| 融券卖出 | `0x1462` | `0x1946` | 未录（`flash::kKinds` 只收前三种）                                 |

- 下单步骤（`Broker::order_steps`，「名 → 函数」表，各步结果写进本单上下文）：切换 → 开窗 → 填单 → 确认 → 回报；开窗 / 确认 / 回报同形「做一个动作、等它弹出的对话框」（`ui::popup`），任一步不符或超时即停、已弹出的窗口留给人工。
  - 切换：注册消息 `Stock` 投给主窗，`wParam` = 市场前缀 × 10⁶ + 代码（深 6、沪 7，北交所没有），等主窗标题换成「…-名称]」；客户端查着时照样处理（实测 0.1s 内换过来）。
  - 填单：核窗内代码与限价委托；价按默认价的小数位格式化；股数以最大可买 / 可卖封顶（改价后客户端未必即时重算，按价反比折一份取小）；数量单位为「元」时填 ⌈股数 × 价⌉、以「预估金额:…(N股)」（`8915`）核股数。写入后 `EN_CHANGE` 会先改写一下，等读回恰为所写。
  - 确认 / 回报：标题「买入交易确认」「卖出交易确认」「交易确认」/「提示」，正文 `Static` 7013、确认 `Button` 7015；确认框核代码 / 价 / 量，回报成功含合同号、失败含错误码与原因；等回报框、确认框、闪电窗都关了才算完。`BM_CLICK` 会被模态框阻塞，一律异步投递。
- 撤单：切撤单页，双击委托行后对话框收私有消息 `0x5554`，确认框正文含类别、方向与合同编号。
- 回包：应答到了，通讯层给请求窗口（查询即该页）发 `0x1788`，`wParam` 似递增序号，`lParam` 是插件发送时给的：页的查询 `0x325`、持仓页的资金那问 `0x324`；下单时序里另见过 `0x326` 撤单 / `0x33F` 开窗查询。

### 请求层（`Req.hpp` `shim vt` `shim probe schema`）

界面上的每一问都由交易插件（`AddinStock.dll`；信用资产 / 融资负债经 `AddinCredit.dll`）建一个 `tc.dll` 的 `CTcComm::CTcJob`（RTTI 名 `CTcJob@CTcComm`，虚表 62 槽），设功能号、写入参、发送；应答到了插件再从同一个 job 上逐行逐字段读出画表。job 成池复用（一轮约 7 个地址），其会话为 `CTcComm::CTcClient`。

| 槽      | 签名（thiscall，自弹字节实测）      | 作用                                                            |
| ------- | ----------------------------------- | --------------------------------------------------------------- |
| 0 / 1   | `()`                                | 加 / 减引用（返回计数）                                         |
| 6 / 16  | `(WORD 功能号)` / `()`              | 设 / 取功能号（取回在低 16 位）                                 |
| 7 / 9   | `(字段号, 值, 0)` / `(字段号, int)` | 写字符串 / 整数入参                                             |
| 25      | `(hwnd, 0x1788, lParam, 0)`         | 发送：应答到了给 hwnd 投 `0x1788`                               |
| 22 / 39 | `()`                                | 应答列数 / 行数                                                 |
| 41      | `()` → 1                            | 游标移到下一行                                                  |
| 43 / 44 | `(列号 / 字段号, buf, 长, 0)`       | 按列号 / 字段号取当前行的字段（字符串；字段号不在应答里返回 0） |

- 协议字典（`shim/Schema.hpp`）：TcApi 缓存 `T0002/wt_cache/TcApi_Cache/40-BRANCH-<营业部>-2.TCS`，登录时整份读进内存（目录里另有别的营业部 / 旧账户的缓存，认字典段原样在堆里的那份）。内容：INI 文本（`WTGN_<序>=<功能号>,<名称>` 列部分功能名）、字段字典（`u16` 条数 + 每条 35 字节 `{u16 字段号, u8 类型, u8, u16 宽度, GBK 名称}`，1091 个）、功能定义（`u16` 流，每条 `{0x4bd, 入参数, 功能号, 入参…, 出参数, 功能号+1, 出参…}`，505 个）。
- 入参：公共的有 `0x79` 资金账号、`0x7b` 股东代码、`0x7d` 账号类别、`0x7e` / `0x7f` 起止日、`0x84` 币种、`0x16a` 页面标识（`PC.Credit.<名>`，如持仓 `zjgf`、资金流水 `zjls`）；`0x580` `0x1484..0x1491`（全链路跟踪、TC 连接号、GUID 等）由 tc.dll 自填。
- 应答：列序即出参序。持仓页一查两问：1228 持仓 + 104 页顶资金那行（`lParam 0x324`）。插件读法：持仓页按字段号（槽 44，画表时字段号带 `0x120000`、逐显示列一次），信用 / 资金流水页按列号（槽 43）。
- 日志（`Req.hpp`）：接入时（`Broker::connect`、`shim test`）按 RTTI 找到 job 虚表、读协议字典，常驻钩住、只记槽 1 / 6 / 7 / 9 / 18 / 22 / 25 / 39 / 40 / 41 / 43 / 44（22 / 39 / 43 / 44 记返回）。每问 `done` 后取出其间的调用，按 job 拼成请求（自首个入参起），各记一条 `req`：功能号与名称、页面标识、发起的插件、入参（字段名 → 值，密码打码）、回包目标、发出到网络线程收到 / 插件开读 / 插件读完（插件减引用）的 ms、列数行数、读法、首行（字段名 → 值）；人点的、客户端定时查的一并记，以 `ago` 区分。查询键恢复比插件读应答早几到十几 ms，故等发出不久的请求读完（至多 2s）再记。实测一问：网络往返约 0.27~0.6s，插件读 37 行持仓约 0.35s。
- 信用委托（旧录，未复核）：功能号 `0xCA`，路由字段 `0x4C1` = `"SDX.ORDER,"`。
- 追踪（`shim.c` 的 `vt`）：只换虚表里的函数指针、不碰代码；桩 `push 槽记录; jmp vt_common` 保存全部寄存器、记进入（槽 / this / 返回址 / 栈上 4 参数及所指头 40 字节）后原样跳回，不必知道调用约定。`vt ret` 点名的槽另把返回址换成 thunk（本线程影子栈配对），返回时记 eax、参数所指与自弹字节；异常越过被钩函数会留下影子栈记录，故只给要看结果的槽开。页保护只改恰好要换的几格：tc.dll 里多改一格（哪怕同页）`VirtualProtect` 即拒（err 5）。

## 四、Broker（`Tdx.hpp`）

- 发布：`State` 不可变、`ver` 变即换了一份；各样为 `Got{v, at}`（值 + 读于几时），按刷新序 成交 / 持仓 / 挂单 / 信用账户；盯着的两样（成交、持仓）换代了才换值。
- 盯持仓线程（有人在看才转）：每 0.1s `follow` 持仓；每 60s 全量扫出成交与持仓（补全活动块唯一校验、跟上客户端换进程）；出过错即下一步先接回客户端、全量重扫。
- 刷新线程一轮：成交、持仓依次切页签、查完 `answered` 全量读（两次查询间又有成交即对不上，连查至多 2 遍）→ 挂单、信用资产、融资负债接成一串 `Chain` → 回持仓页（也等查完再放界面锁）；每查完一样即发布。`Part::Fills`（调仓等卖单成交时）只查成交。
- 起因：`request`（不等）/ `sync`（等刷完，失败即 `Fail`）/ 有人在看而没刷过或距上轮满 `every` 秒（缺省 60s）/ 下单成功后 1s 与 6s / 客户端自己重查的持仓与成交对不上。有人在操作客户端（`idle` < 60s）时，定时与对不上推到无输入满 60s 之后。失败不重试。
- 两融条款（`Credit.hpp`）：功能树开「标的证券查询」「担保品查询」各点「查询全部」，查完读整表、行数须恰为页上条数（担保品近万只，其间只看查询键）；合成 `代码 → Term`，跨市场同号的只留 `market_of` 那只。
- 信用账户：担保资产、可融额度余量（最高融资额度 − 融资负债含费用）、负债总额、净资产、可用保证金、现金资产、各只负债（数量, 金额），与同一轮持仓。
- 资金流水（`Flow.hpp`）：开「资金流水」页（等开页那一问查完才敲起止日），按 30 天一窗设起止日、点查询等查完，N > 0 即取新冒出的恰 N 行的块。
- 事务：下单 / 独占 / 两融条款 / 资金流水同形 `txn(名, 字段, fn)`——开段、占界面锁、接上客户端（shim 不在线即注入，请求层日志随之钩上）、当前线程跑 fn。界面锁 `Gate` 带占用者名字、同线程可重入；刷新一轮在各样之间 `yield`（三问一串之内不让），下单至多等一样查完。

## 五、shim 独立程序（`src/live/tdx/shim/`，产物 `build/bin/shim`）

摸客户端、验收适配都在这里，靠日志与断言、不靠肉眼。与 `app_main` 共用同一份适配代码（CMake `app` object 库）；在仓库内运行，shim.dll 不在线即编译 + 注入。界面动作只做查询类，不下单。

| 子命令                                              | 做什么                                                                                        |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `shim cmd <命令…>`                                  | 原样发一条 shim 命令，应答逐行 JSON                                                           |
| `shim probe tables` / `text <词…>`                  | 堆里全部明文表（址 / 副本数 / 行列数 / 表头 / 前几行）/ 各词按 GBK、UTF-16LE 逐处列出前后字节 |
| `shim probe obj <址>` / `ref <值>` / `class <类名>` | 对象逐字标去处（模块+偏移 / RTTI 类名）/ 堆里谁存着这个值（所在对象 + 字段偏移）/ 类的虚表    |
| `shim probe schema [功能号…]`                       | 协议字典：各功能一行 / 某功能的入参与出参（字段号 + 名称）                                    |
| `shim rec <秒>`                                     | 录制消息 / 窗口树 / 绘制层的变化 → `output/run/live/tdx/rec/<时刻>.jsonl`                     |
| `shim vt <秒> <类名>[=槽,…]`                        | 虚表追踪：每次调用（参数、所指文本、点名槽的返回）→ 同上目录                                  |
| `shim test [用例…]`                                 | 在线用例（空 = 全部不慢的，`list` 列出）；一例一行 PASS / FAIL，细节在交互日志「用例 <名>」段 |

用例（`Test.cpp`）钉住三类东西：适配各路径（`query` 各页查一次、`answer` 查完即读与 Chain、`flow` 资金流水、`terms` 两融条款）、实测的客户端行为（`busy` 查着时切页签被吞）、`Tables.hpp` 列声明对协议字典（`fields`）。客户端升级后先跑一遍。
