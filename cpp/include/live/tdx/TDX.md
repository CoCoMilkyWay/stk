# 通达信（国金证券版）适配

Wine 里跑通达信客户端 `TdxW.exe`，实现 `live::Broker`（`live/Broker.hpp`）：读走进程堆里的明文表，写与重查经注入的 shim 驱动界面。上层（`gui/task_live`）只认 Broker，行情、持仓帧、调仓试算都在券商无关的一层（`live/Board.hpp` `live/Book.hpp` `live/Rebal.hpp`）。

安装目录软链：`/home/chuyin/work/tdx/zd_gjzq` → `~/.wine/drive_c/zd_gjzq`

## 架构

```
TdxW.exe（Wine）
├── 进程堆     /proc/<pid>/mem   Mem / Tables   明文表：持仓 / 成交 / 挂单 / 信用资产 / 融资负债 / 标的证券 / 担保品
└── shim.dll   TCP 控制通道      Shim / Win     窗口树 / 绘制层 / 消息 / 输入 / 请求追踪
                                 Ui             通达信界面：主窗 / 交易栏与功能树 / 查询页 / 弹框
                                 Flash Credit   闪电下单 / 两融条款与信用账户
Tdx（Broker）  盯持仓线程 + 刷新线程 + 界面锁 Gate
Console        调试台（Live 的 Client 页，ImGui）
```

- 读只经进程内存；写只经 shim 操作客户端界面，客户端自己负责登录会话与交易通讯。
- 客户端状态与预期不符（界面没弹出 / 内存正被改写 / 回报失败）是外部结局：`fail` 抛 `Fail`，在各轮 / 各事务的边界收成原因文本；本程序自身的不变式一律 `assert`。不重试，等下一个起因。
- 等待一律经 `Until.hpp`：`poll` 等到即回、超时回空（调用方另有退路），`until` 超时即 `Fail`（报出当时的状态）。
- 交互日志经 `Trace.hpp`：shim 命令与应答、读内存的换代与应答、外部进程、Broker 的轮次 / 下单 / 两融条款按段（`Span`）一行一事件，落 `output/run/live/tdx/log/<启动时刻>.jsonl`。段内有事件才落盘，相邻同样的事件并成一行 `rep`；适配里的 `fail` 先在当时的段路径下记一行再抛；调试台在段外，不记。事件种类与字段见其文件头。

## 一、内存明文表（`Mem.hpp` `Tables.hpp`）

客户端查过的表，解密明文驻留在 `TdxW.exe` 堆里。

### 堆

- `Heap`：pid + 常开的 `/proc/<pid>/mem`（各线程共用，`pread` 不带状态）；堆段 = 可读写、私有、非文件映射（Wine 堆即匿名 `rwxp`），跳过 400M 以上的段（Wine 堆约 580M）。
- `scan(形状们)`：段间并行（至多 4 线程，各一段一缓冲），同锚点的形状共一遍查找，命中按段序；`near` 给定时只扫含其中任一地址的段。`each` 逐段顺序读（调试台探内存用）。
- `attach`：找进程（`comm` 或 `argv[0]` 为 `tdxw.exe`）、确保有读权限、开堆；`ptrace_scope ≠ 0` 时用 `output/config/live/.sudo_pass` sudo 关一次，到重启前有效。

### 表的四条轴

格式：GBK，`\r\n` 分行、`|` 分列，首行表头 `0|…|`。每张表一份声明（`Tables.hpp`），由四条互不相干的轴拼成，流程只此一份：

| 轴   | 声明                                                                                                                                          |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 形状 | `kShape{name, head, row, empty, slack}`：表头 / 数据行模式；空表算不算块；复读窗口在块尾外多留的字节                                          |
| 列   | `kViews` 各布局列数；`kCols = tuple{col<&Row::成员, as::转型>(各布局列号…)…}`（`kNone` = 该布局没有，成员 `nullptr` = 只核不存）；`check(行)` |
| 读法 | `Mode`：`Live` / `Union` / `Ask` / `Whole`                                                                                                    |
| 索引 | `Index`：`Unique<键>` 键不重 → `Keyed<行>` / `Tally` 成交按代码合计 → `Keyed<Flow>` / `Pairs` 名称不重 → 名称 → 数值原文                      |

- 模式：字面量 + 记号。`{n}` 行数、`{t}` 标签、`{d}` 不取（≥ 1 位数字；带位数 K 如 `{t8}` 即恰 K 位），`{code}` 6 位代码，`{clock}` `HH:MM:SS`，`{name}` 非数字打头的非空列，`*` 任一列，`...` 其后任意（再跟的字面量须恰为行尾）；数据行不许有 NUL。
- 表头带 `{n}` 即块只取前 n 行（后随不足 n 行 = 被覆盖了一半的旧缓冲 / 分页块，不算），不带即整块。
- 锚点：表头最长的字面段（末段连 `\r\n`）；段内找锚点，往前至多（锚点前各记号的最宽 + 字面段）字节找表头起点。
- 转型 `as::*`：`text` `name`（非空）`code` `clock` `num` `num_or`（空 = 无）`flag`（沪深标志 0 深 / 1 沪 / 60 北）`side`（买入 / 卖出 → +1 / −1）`sides`（两列买 / 卖）`groups`（三组「名称|数值|」）`is<"字面">`（只核）。

### 流程

- 一张表：扫 `Heap::scan` → 选 `Mode::choose` → 按址连读一致 `stable`（躲开 torn read）→ 解析校验 `parse` → 合并 `Mode::merge` → 索引 → 快照 `Snap{heap, mark, rows, index}`（不可变，`==` 即同一代）。
- 校验：块级 GBK 无非法字节、列数全表一致且为已知布局；行级各转型与 `check`；索引键不重。任一不过即 `Fail`。
- 读法 2 × 2：

|          | 取最新一份（没见过的） | 取累积               | 入口                                 |
| -------- | ---------------------- | -------------------- | ------------------------------------ |
| 被动换代 | `Live` 活动块          | `Union` 当日副本并集 | `follow` / `wait`                    |
| act 驱动 | `Ask` act 后新冒出的块 | `Whole` 整块拼到齐   | `arm` + act + `read`（`Chain::ask`） |

- `follow(snap)`：没换代回原快照，换代即重扫再选；`wait(snap)` 轮询 `follow` 等客户端重查后的换代（应答与旧的逐字节相同即超时后全量读）。
- `Chain`：接连几问（几张 act 驱动的表各 act 一次），每遍扫齐各表，等到上一问应答的那遍即下一问的 act 前。

### 四种读法的依据

- 活动块（持仓）：每查网络缓冲留一份 `n = 行数` 的副本（永不更新）；客户端在用的活动块 `n = 0`、全进程唯一；重查即另写一块，旧块要过几秒到几十秒才释放，其间几块并存、内容不一：记下扫到过的各块（最近 256 块），新冒出的即在用的，没有新冒出的即仍是上次选的；头一次扫就几块不一（定不出）即 `Fail`，旧块释放后自愈。新旧活动块在同一堆段来回换址：`follow` 复读旧块比字节（约 0.03ms），换代后先只重扫该段；点「刷新」后约 100ms 换代。
- 副本并集（成交）：每查留几份副本、旧副本不即时释放、无活动块标记；成交只增不改，当日全部副本按（成交编号, 委托编号, 代码）取并集，同号逐字段一致。没换代即上次各副本所在的段里没有新副本。无成交时只回 `0||0||P|`（不带日期，认不出），只能等一会儿全量读。
- act 后新冒出的块（挂单 / 信用资产 / 融资负债）：每查在新址留一两份、旧的不释放，同一次应答各份逐字节相同，表内无新旧标记，只认 act 后新冒出的块。空表 `0||0||P|` 与无成交的成交表同形；挂单与融资负债同形、按行首（时间 / 市场标志）可分。挂单切页签自带一次查询，故切页与刷新同在一问内。
- 整块拼到齐（标的 / 担保品）：页上「查询全部」后客户端分页收应答（每页一块），收齐另拼一整块；标的表头带总数，担保品分页块 `0||<该页行数>||P<定位串>|`（不认）、整块不带总数，收齐与否对页上条数。整块可能留着几份（每查全部一次一份），须同内容。两表跨市场同号（沪市债券与深市基金），以（市场, 代码）为键。

## 二、消息桥（`Shim.hpp` `Win.hpp`，源码 `src/live/tdx/win32/`）

- 构成：`shim.c` 注入 `TdxW.exe` 后开 TCP 控制通道；`inject.c` 远程 `LoadLibraryA`。
- 构建：交叉编译 clang + mingw 运行时优先、`i686-w64-mingw32-gcc` 次之；产物按源码哈希 H 命名 `shim_<H>.dll`、端口 `20000 + H % 10000`，落 `output/run/live/tdx/shim/`；改源码即换新 DLL、新端口，旧产物自动清理。
- 注入：DLL 拷进 wine 的 `C:\windows\temp`（不依赖 Z: 盘映射）、写端口文件，`inject.exe` 远程加载（`WINEPREFIX` 取环境变量或 `~/.wine`，目标进程名 `SHIM_TARGET_PROC` 或 `tdxw.exe`）。
- 接入（`win::attach`）：shim 不在线即编译 + 注入，再开 `noraise`（重扫模块，补钩注入后才加载的 DLL）与 `gdi`（首次装入口钩子并重绘全部窗口）。
- 协议：请求一行 `cmd arg...`，应答 0..N 行 JSON 加末行 `ok` / `err <原因>`；一次一条连接，shim 串行应答；`target` 为 `0x..` 或 `class=<类名>`。窗口句柄一律是 shim 给的 `0x%08x` 串（`win::Hwnd`），原样回传。

| 类别   | 命令                                            |
| ------ | ----------------------------------------------- |
| 窗口树 | `tree` `enum` `find` `treegen` `treewatch`      |
| 控件   | `gettext` `settext` `rect` `detail` `highlight` |
| 动作   | `post` `send` `regmsg` `click` `clickat`        |
| 输入   | `mouse` `key` `char`                            |
| 绘制层 | `gdi` `gdidump [target]` `gdiwatch`             |
| 请求   | `req on\|off\|clear\|drain` `req attach`        |
| 其它   | `noraise` `spy` `ping` `help`                   |

记录：

- 节点：`{depth,hwnd,id,class,title,rect,style,exstyle,vis,en}`，先序、depth 定父子、兄弟序即 z 序；WinEvent 钩子维护变更版本号。
- 图层：`{hwnd,off,items:[[l,t,r,b,v,文字?]]}`，客户区坐标、后出的在上；`gdi` 与 `detail` 同形，`v` 分别为颜色与状态位。
- 快照 / 推送成对：`treegen` / `treewatch`（版本号）、`gdidump` / `gdiwatch`（图层）；长连接无变更 1s 推心跳 `null`、不收尾。

机制：

- 子项：`detail` 在目标线程内一次读完 Button / ListBox / Header / ListView / TreeView / 弹出菜单的可见项。
- 输入：一律进程内 `PostMessage`，不动真实光标、不抢前台；鼠标投给捕获窗口或坐标下最深子窗口，键盘投给焦点窗口。
- 钉光标：交易功能树等控件只认 `GetCursorPos` / `GetMessagePos` 处的点击；`clickat` / `mouse` 投递前改写这两个入口，500ms 内回投递点。
- 不抬窗：各模块 IAT 里的 `NtUserSetWindowPos` / `NtUserDeferWindowPosAndBand` 换成去掉 z 序变化的包装；新弹出的菜单、对话框仍到最前。
- 绘制层：自绘控件（`CFQS_*` / `MHPToolBar` / `Afx*`）上的按钮只是画出来的字。`TdxW.exe` 有 VMProtect 壳、不走 IAT，Wine 的 win32u 层已是字形索引，故改写 gdi32 / user32 的 18 个绘制函数入口，按「后画盖先画」维护每个窗口可见的文字与色块。`win::click_text` 在其中找文字恰为所给的项、投递其中心点的单击（候选窗口恰一个即只取它的图层）。
- 卡顿：客户端查大表时界面线程卡住（担保品查询全部约 100s），走界面线程的命令（`gettext` 等）随之等待；调用方按需给长 timeout。
- 管不到：内嵌 CEF 网页（消息中心等）。

## 三、交易链路

交易连接 7703（`tc.dll` 内含 OpenSSL，套接字上只见 TLS 密文），行情 7709 / 7711（明文）。交易不复刻协议：下单经 shim 操作闪电窗（界面层）；请求层是进程内已登录的 session 与请求对象，目前只追踪、不发送。

闪电窗：主窗 `WM_COMMAND` 打开，随后图表视图收一条私有消息（`lParam` 疑为客户端内部证券编号）。闪电窗只认图表当前证券。

| 委托     | 主窗命令 | 图表消息 | 控件 id（代码 / 价 / 量 / 单位 / 报价方式 / 最大可买·可卖 / 提交） |
| -------- | -------- | -------- | ------------------------------------------------------------------ |
| 买入     | `0x13DD` | `0x1947` | 12005 / 12006 / 12007 / 12016 / 3067 / 2022 / 1                    |
| 卖出     | `0x1404` | `0x1948` | 12005 / 12006 / 12007 / 12016 / 3067 / 2065 / 1                    |
| 融资买入 | `0x1441` | `0x1945` | 313 / 314 / 315 / 320 / 220 / 199 / 1                              |
| 融券卖出 | `0x1462` | `0x1946` | —                                                                  |

`flash::kKinds` 只收前三种；融券卖出的控件未录。

- 步骤（`Broker::order_steps`）：切换 → 开窗 → 填单 → 确认 → 回报；开窗 / 确认 / 回报同形「做一个动作、等它弹出的对话框」（`ui::popup`），任一步不符或超时即停在那一步、已弹出的窗口留给人工。
- 切换：通达信外部联动——注册消息 `Stock` 投给主窗，`wParam` = 市场前缀 × 10⁶ + 代码（深 6、沪 7，北交所没有），等主窗标题换成「…-名称]」；不走按键（客户端回报后忙着时投递的键盘消息会落空），标题没换过来每 1s 重投、切到同一只重投无副作用。
- 填单：核窗内证券代码与限价委托；价按默认价的小数位格式化；股数以闪电窗最大可买 / 可卖封顶（改价后客户端未必即时重算，按价反比折一份取小）；数量单位为「元」时只收整数元、客户端按价向下折股，填 ⌈股数 × 价⌉ 并以「预估金额:…(N股)」（`8915`）核对股数。写入后客户端的 `EN_CHANGE` 处理会先改写一下，等读回恰为所写。
- 确认 / 回报：标题「买入交易确认」「卖出交易确认」「交易确认」/「提示」，正文 `Static` 7013、确认 `Button` 7015（`ui::body` / `ui::yes`）；确认框核代码 / 价 / 量；回报成功含合同号，失败含错误码与原因；等回报框、确认框、闪电窗都关了才算完。同步 `BM_CLICK` 会被模态框阻塞，一律异步投递。
- 撤单：`WM_COMMAND 0x2716` 切撤单页；委托列表 `SysListView32` id 1567（文字从绘制层读）；双击行后对话框收私有消息 `0x5554`，确认框正文含类别、方向与合同编号。
- 回包：通讯层给请求窗口发 `0x1788`，`wParam` 似递增序号；`lParam` 按时序为 `0x324` 委托 / `0x326` 撤单 / `0x325` 刷新查询 / `0x33F` 开窗查询。
- 交易栏：主窗 `TdxW_MainFrame_Class`；页签与「刷新」画在 `MHPToolBar` / `MainViewBar` 上；左侧功能树 `SysTreeView32` id 59653 只给可见项，滚到顶后逐页往下找；交易栏收起（功能树不可见）即点主窗顶栏「交易」（`AfxWnd100`）展开。撤单页上另画着一个撤单动作键，故切去时须在持仓页、页签唯一。
- 查询页：条数标签 `Static` 166（「第1--N条」/「共N条」，重查中清空）、「查询全部」按钮 454；表头 `SysHeader32` 的列名从 `detail` 读。

### 请求层（`shim req`）

- 入口：`TC_DoLevinJy` 是闪电交易的界面入口；`JYConfirm` `CANCLENOTIP` `YMSENDNOCONFIRM` 为确认框配置。请求层下单不经下单窗与确认框。
- session：宿主对象 vtable `+0x26C` 返回 session；session `+0x1C(0, 0)` 创建请求对象。
- 请求对象（`AddinCredit.dll` 信用委托所见）：

| vtable          | 方法     |
| --------------- | -------- |
| `+0x14`         | 初始化   |
| `+0x18`         | 设功能号 |
| `+0x1C`         | 写字符串 |
| `+0x24`         | 写整数   |
| `+0x2C`         | 写浮点   |
| `+0x64`         | 发送     |
| `+0x6C`         | 等待     |
| `+0x88` `+0x90` | 访问响应 |

- 信用委托：功能号 `0xCA`，路由字段 `0x4C1` = `"SDX.ORDER,"`。
- 追踪：`req attach <hwnd> [offset]` 经 MFC42 `CWnd::FromHandlePermanent` 取顶层窗口的 `CWnd`，扫其中宿主指针（多个候选只回偏移、须显式给 `offset`），建一个空请求认出 vtable，钩初始化 / 功能号 / 字符串 / 整数 / 浮点 / 发送六个方法：先记参数、再原样调用。事件入 4096 条环形缓冲：公共 `{tick,tid,obj,op}`，`func` / `init` 带 `value`，`str` 带 `id,aux,value`，`int` / `float` 带 `id,value`，`send` 带 `args`。
- 录制：调试台录制器开始即 `req on` `req clear`，每轮 `req drain` 以 `kind="req"` 并入同一 JSONL，停止即 `req off`。

## 四、Broker（`Tdx.hpp`）

- 发布：`State` 不可变、`ver` 变即换了一份；各样为 `Got{v, at}`（值 + 客户端重查后读于几时），按一轮的刷新序 成交 / 持仓 / 挂单 / 信用账户；盯着的两样（成交、持仓）换代了才换值。
- 盯持仓线程（有人在看才转）：每 0.1s `follow` 持仓；每 60s 一遍全量扫出成交与持仓（补全「活动块唯一」校验、跟上客户端换进程）；出过错即下一步先接回客户端（shim 不在线即重注入）、全量重扫（重找进程）。
- 刷新线程一轮：成交、持仓依次点页签与「刷新」、`wait` 等换代（两次查询间又有成交即对不上，连查至多 2 遍）→ 挂单、信用资产、融资负债三问接成一串 `Chain` → 回持仓页；每查完一样即发布，不等整轮。
- 起因：`request`（不等）/ `sync`（等刷完，失败即 `Fail`）/ 有人在看而还没刷过或距上轮满 `every` 秒（缺省 60s，0 = 不定时）/ 下单成功后 1s 与 6s（`kick`）/ 客户端自己重查的持仓与成交对不上。失败不自动重试，等下一个起因。
- 两融条款（`Credit.hpp`）：功能树开「标的证券查询」「担保品查询」各点「查询全部」，等内存里拼出行数恰为页上条数的整表（担保品近万只，客户端卡一两分钟；条数标签另起线程读，内存照读不受卡顿影响）；合成 `代码 → Term`，跨市场同号的只留 `market_of` 那只。
- 信用账户：担保资产、可融额度余量（最高融资额度 − 融资负债含费用）、负债总额、净资产、可用保证金、现金资产，各只负债（数量, 金额），与同一轮持仓股数。
- 锁：界面自动化（刷新、下单、两融条款、调仓整批）共用 `ui::Gate`，带占用者名字，同一线程可重入。
